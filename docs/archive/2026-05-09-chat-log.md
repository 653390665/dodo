# InkFlow 对话归档

日期：2026-05-09
说明：这是本轮开发协作对话的结构化归档，不是平台原始逐字导出，但已尽量按主题与推进顺序保留关键决策、问题、修复与结论。

## 对话主线

### 1. 启动失败与本地运行恢复

- 用户反馈 `npm run dev` 启动时报 `tsx: command not found`
- 诊断出依赖未正确安装与包管理状态不一致
- 修复本地运行环境后，确认开发服务恢复

### 2. 首页黑屏与前端 Node-only 依赖问题

- 用户反馈网站卡住、页面打不开
- 诊断出浏览器端引用了 `fs/path/os` 等 Node-only 模块
- 调整配置读取方式，改为前端通过服务端配置接口读取
- 网站恢复正常渲染

### 3. 创作舞台布局重排

- 用户多轮指出：
  - 空白区浪费严重
  - 编辑区太小
  - 智能管家入口不清楚
  - 右侧长期空白
- 连续做了多轮布局修复：
  - 章节侧栏默认收起
  - 主编辑区优先
  - 智能管家改成覆盖式抽屉
  - 右侧空白根因定位并修复

### 4. 智能管家与正文链路稳定性

- 测试确认：
  - 分镜可生成
  - 审计可返回
  - 连续正文生成早期存在不稳定和 `502`
- 后续确认：
  - 不是没配 API
  - 是上游模型稳定性与前端流式解析问题
- 修复了 SSE 解析逻辑与超时/重试策略

### 5. Prompt 优化主线

- 用户希望强化提示词的约束力和效果
- 先统一评估优先级，决定优先优化“正文链路”
- 连续多轮优化：
  - `orchestrateWriter`
  - `manualAudit`
  - `orchestrateCritic`
- 关键关注点：
  - 完整句
  - 信息释出节奏
  - 台词承接
  - 动作兑现
  - 减少解释味

### 6. 审计后自动精修链

- 先尝试整章自由重写式 `chapter-polish`
- 多次出现：
  - 重复段落
  - 整体跑偏
  - 分数回退
- 决策改成方案 A：
  - 基于审计点名片段的局部手术式修补
- 随后完成：
  - `chapter-polish.ts`
  - `surgical-patch` 模式
  - 结构化审计输出
  - 高影响目标优先级

### 7. Skill 系统

- 用户提出：
  - Skill 不应是单张融合卡
  - 应支持多个维度、可组合装配
  - 装配应有打分与反馈
- 随后完成：
  - 技能仓库版本化
  - 详情编辑
  - 版本谱系
  - 试驾对比台
  - 装配卡槽
  - 反馈记录与推荐排序

### 8. 拆书工厂

- 用户指出：
  - 现在只显示一张融合卡不合理
  - 维度应该拆开
  - 维度需要评分和建议装配位
- 当前已完成前端层修复：
  - 自动按维度拆成多卡
  - 每张卡有建议装配位
  - 每个维度有评分与强度标签

### 9. 设置页与提示词工作台

- 用户反馈设置弹窗布局混乱、显示不全
- 已完成：
  - 模型设置与提示词调试区分层
  - 模板目录、正文、验证区重排
  - 底部操作区固定可见

## 关键决策记录

### Prompt 优先级

- 优先：正文链路
- 次优：技能链路
- 最后：外围链路（灵感 / 大纲）

### 局部精修策略

- 放弃“整章自由改写”
- 转向“审计驱动局部修补”
- 先做确定性去重，再做局部 patch，再做护栏校验

### Skill 形态策略

- 先在前端结果层把融合卡拆成多维度卡
- 后续再推动后端 `extract-skill` 原生返回 `skills[]`

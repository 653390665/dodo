剩余改善建议（V3→V4）
P2-1: prompt-governance-catalog.ts 仍有 1218 行

虽然比 V2 的 2064 行好了很多，但仍是全库最大文件。建议按 governance flow（extract / score / recommend / accept）拆成 3-4 个模块。非阻塞。

P2-2: EditorView.tsx 788 行 — 组件拆分窗口期

14 个组件超过 400 行，其中 EditorView 最大。建议提取编辑器工具栏、状态栏、快捷键面板为独立子组件。非阻塞但影响新开发者理解速度。

P2-3: 12 处 as unknown as 类型转换

比 as any 安全（强制两步转换），但仍绕过了类型检查。主要集中在 DB 行映射层。建议为 better-sqlite3 行定义精确的 Row 类型。

P3-1: vitest.config.ts 与 node:test 运行器不匹配

项目配置了 vitest.config.ts，但实际测试使用 node:test + node:assert/strict，通过 tsx --test 运行。两者不冲突但容易混淆新开发者。建议删除 vitest.config.ts 或在 README 中注明测试运行方式。

P3-2: 13 个过时依赖含大版本跳跃

express 4→5、vite 6→8、typescript 5→6、electron 42→43 等均为破坏性升级。建议在商业化稳定后统一规划一次大版本升级 sprint，当前不建议逐个升。

P3-3: 12 处 console.* 调用

大部分是 console.warn 用于前端错误边界和 SSE 监听器异常处理，可接受。服务端 3 处在 logger.ts 内（合理）。建议前端引入统一错误上报机制替代散落的 console.warn。

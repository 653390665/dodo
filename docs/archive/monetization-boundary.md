# InkFlow 权益与商业化边界

验证日期：2026-08-09

## 当前状态

InkFlow 当前处于 Beta 阶段，没有接入真实支付、订单、订阅、到期、退款或恢复购买系统。默认构建关闭商业化门禁，现有额度数字只用于商业化实验，不应阻断正常创作。

用户自行配置模型 API Key（BYOK）时，基础 AI 创作主链由用户直接承担模型服务成本，InkFlow 不应再按平台模型成本限制这部分调用。

服务端调用点必须明确区分 `basic-byok` 与 `enhanced-workflow`。该分类不接受客户端请求字段覆盖：基础 BYOK 只校验作品和数据库代际，不占用平台实验额度；高级生产、批量审稿等增强工作流可在商业化实验中使用独立额度。

## 当前权益

| 范围 | Beta 默认权益 | 边界 |
|------|---------------|------|
| 本地写作与数据 | 可用 | 正文、设定、作品管理和一致性备份不属于付费门禁 |
| BYOK 基础 AI 主链 | 可用 | 依赖用户的 API Key、网络和模型服务状态 |
| 增强工作流与授权技能 | Beta 默认开放 | 当前开放不代表已购买、永久权益或未来定价承诺 |
| 托管模型调用 | 尚未提供 | 未来如提供，应按独立模型额度和实际成本计费，不与 BYOK 混合 |

## 实验开关

只有前后端同时显式启用时，商业门禁实验才可对用户生效：

- 服务端：`INKFLOW_ENABLE_MONETIZATION=true`
- 前端构建：`VITE_INKFLOW_ENABLE_MONETIZATION=true`

只开启其中一侧会造成界面权益与服务端执行不一致，因此不属于受支持配置。测试环境可单独启用旧额度策略，用于验证限额、并发预留和退款逻辑。

商业化实验开启后，前端增强能力只认作品中由服务端持久化的 `commercialMode='paid'`。浏览器本地访问码、localStorage 标记或客户端自报字段都不是可信权益，不能绕过服务端门禁。

通用 `/api/db` 只是业务数据代理，不是权益发放通道。客户端可在 `free` 与 `strict` 之间调整写作治理模式，但不得经该接口写入 `paid`、重置用量或抬高配额上限；这些字段只能由受信服务端流程变更。

当前实验状态仍与作品一起保存在用户可控的本地 SQLite 和整库备份中，因此只能用于验证能力分层和交互，不是抗篡改的购买凭证。显式开启实验也不代表可以用于正式收费；在独立服务端权益账本、签名声明或等价可核验机制上线前，正式商业化必须阻塞。

## 未来候选边界

- Free：本地写作、本地数据、BYOK 基础 AI 主链。
- Pro：高级连续工作流、授权资产、跨章连续性治理、批量审稿等可验证的增值结果。
- 托管模型额度：独立计量和计费，明确展示用量、成本与失败退款规则。

上述分层是产品方向，不是当前售卖承诺；价格、配额和上线时间需要经过用户价值与付费意愿验证。

## 正式商业化前置条件

商业门禁正式启用前，至少需要：

1. 独立于用户可编辑 SQLite/备份的服务端可信 entitlement，不以浏览器或本地数据库状态作为购买凭证。
2. 可核验的订单、订阅状态和到期时间。
3. 退款、取消、恢复购买和跨设备同步机制。
4. BYOK 与托管模型用量分账，失败请求不重复扣费。
5. 清晰的能力矩阵、价格、服务限制和用户协议。

在这些条件完成前，界面不得使用“立即购买”“永久会员”“无限调用”“VIP 专线”等交易或无限能力承诺。

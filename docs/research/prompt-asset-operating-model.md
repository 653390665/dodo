# Prompt Asset Operating Model

日期：2026-07-03
使用技能：`product-strategy-session`、`roadmap-planning`、`epic-breakdown-advisor`、`context-engineering-advisor`、`customer-journey-map`

## 核心判断

这批提示词不是一堆可复制的 prompt，而是多类产品资产：

1. **作者流程包**：同一作者的一组提示词形成连续写作工序。
2. **题材/文风包**：适配特定题材、平台格式或叙事口味。
3. **任务能力卡**：脑洞、取名、角色、世界观、细纲、正文、润色、审稿等单点能力。
4. **Agent 引导策略**：由系统判断用户当前处境，推荐下一步动作、资产和上下文。
5. **通用工具与 Agent 强化**：命名、脑洞、角色、世界观、审稿这类跨题材能力，要和作者风格流派分开。
6. **发布平台维度**：开书前判断作品准备面向番茄、起点、晋江、知乎、老福特、七猫、飞卢等哪类环境。
7. **Skill Series Flow**：把同作者或同方法论的一组 Skill 编排成连续流程，用户走下一步，不逐条调用提示词。
8. **Deconstruction Skill Cards**：拆书产出的可叠加能力卡，如文风、节奏、钩子、反模式、主编审稿卡。

因此，不能只问“这些提示词挂不挂成 Skill 卡”。更准确的问题是：它们在什么层级被挂载、什么时候被召回、由谁引导用户使用。

详细分类见：`docs/research/prompt-skill-taxonomy.md`。关键规则是“主归属 + 次归属”：同一条世界观/角色/大纲提示词，可能既是作者流程包节点，也能抽象为通用工具，但产品里要先保留它的主归属。

## 资产层级

### 1. Prompt Asset

原始提示词资产。用于保存原始提示词、清洗版本、评分和风险。它不是产品调用的最小单位，复合提示词需要继续拆成 Capability Unit。

用途：

- 质量评估
- 版本管理
- 授权记录与白标状态
- 作为流程包、Skill 卡和 Capability Unit 的原料

关键字段建议：

- `source`: `built-in | square | private | custom`
- `accessTier`: `free | paid | private | built-in`
- `authorFlowId`
- `platformTags`
- `genreTags`
- `taskTags`
- `riskFlags`
- `licenseStatus`: `user-authorized | public | built-in | unknown`
- `sanitizationStatus`: `raw | needs-sanitization | sanitized | runtime-ready`
- `runtimeStatus`: `candidate | direct-use-test | active | deprecated | rejected`

### 1.5 Capability Unit

能力单元是产品内部真正可管理的最小能力。

一条 Prompt Asset 可以拆出多个 Capability Unit。例如：

- 脑洞+背景 -> `ideaSeed` + `worldBibleSeed`
- 书名+简介+正文 -> `titleSynopsis` + `draft`
- 正文+去 AI 味 -> `draft` + `polishPatch`

每个 Capability Unit 必须有：

- 唯一主产物。
- 能力标签。
- 控制层：canon / flow / overlay / diagnostic / utility。
- 输入要求。
- 输出形态。
- 质量门槛。

详细规则见：`docs/research/prompt-dimension-normalization.md`。

### 1.6 Placement Tier

评分后必须决定产品放置，不让高分资产自动变成用户可选项。

放置等级：

- `core-default`：默认内置质量护栏，如审稿、去 AI、连续性。
- `agent-guided`：Agent 在需要时调用，如脑洞、取名、世界观、角色。
- `optional-style`：用户可选的写作体验，如正文文风、平台强风格。
- `flow-default`：用户选择流程后自动推进，如小飞鸡长篇流。
- `premium-enhancement`：高级诊断、长篇稳定性、私有资产编排。
- `sanitize-required`：已授权但未清洗，暂不进入用户可见产品。
- `research-only`：质量不可控、污染高、不可验证，或许可证仍未知的外部来源。

详细规则见：`docs/research/prompt-scoring-and-placement.md`。

### 1.7 Deconstruction Skill Card

拆书卡不是 Prompt Asset，也不等于普通 Skill Card。它来自某本参考作品或一组参考作品，必须带证据和污染约束。

用途：

- 给当前作品临时叠加文风、节奏、钩子、对白、动作链等能力。
- 给审稿和去 AI 味提供反模式、主编审稿、平台适配检查项。
- 给前十章诊断提供对标样本。

关键字段建议：

- `cardType`: `styleVoice | pacing | hook | payoffLoop | characterDynamics | dialogue | actionChain | worldRulePattern | platformFit | antiPattern | reviewRubric | continuityCommit`
- `sourceWorkId`
- `sourcePromptAssetIds`
- `evidenceCoverage`
- `evidenceMoments`
- `contaminationRisk`
- `applicationFitScore`
- `recommendedPlacement`
- `allowedStages`
- `blockedUsage`

放置原则：

- 文风、对白、节奏属于写作体验，默认选配或 Agent 推荐。
- 反模式、动作链、主编审稿属于软件质量，默认内置到审稿/精修。
- 世界规则模式可辅助世界观，但不能把原书设定写入 canon。
- 平台适配卡只有在用户选择平台或开启商业诊断时启用。

详细规则见：`docs/research/prompt-deconstruction-fusion-system.md`。

### 2. Skill Card

用户可感知、可挂载的能力卡。它不一定等于一条 prompt，可以由多个 Prompt Asset 组合而成。

适合做 Skill 卡的资产：

- 文风去 AI 味
- 角色生成
- 世界观生成
- 章纲/细纲
- 正文推进
- 审稿改稿
- 题材规则

但这些需要继续分层：

- 命名、脑洞、角色生成、世界观生成：优先是功能工具。
- 审稿、改稿、逻辑检测：优先是通用主编 Agent/Skill。
- 正文、续写、去 AI 味文风：可能是写作风格流派 Skill。
- 作者成套提示词中的世界观/角色/大纲：优先是 Author Flow Pack 节点，再考虑抽通用版。

不适合直接做用户可见 Skill 卡的资产：

- 未白标清洗的原始定制提示词
- 过长流程的完整原文
- 只服务内部路由的判断规则

### 3. Author Flow Pack

同一作者或同一方法论下的一套连续工作流。它是“风格流程”，不是散卡。

示例：

- **小飞鸡长篇流**：脑洞 -> 世界观 -> 角色卡 -> 大纲 -> 细纲/章纲 -> 正文 -> 拆书 -> 去 AI 味
- **风华短篇/老福特流**：拆爆款/脑洞 -> 大纲 -> 正文/导语 -> 审稿 -> 改稿
- **天马大纲流**：基础大纲 -> 三幕式 -> 设定强化+节奏 -> 通用章节大纲
- **沐殇题材定制流**：宝可梦/克苏鲁世界观 -> 角色 -> 章纲 -> 正文 -> 标题简介

产品含义：

- 用户不需要手动理解每条提示词。
- 选择一个作者流派后，系统在不同阶段自动召回对应资产。
- Author Flow Pack 可以包含免费入口和付费高级节点。

### 3.5 Skill Series Flow

Skill Series Flow 是 Author Flow Pack 的可执行形态。它不是简单列表，而是一组带步骤、变体和门槛的流程。

每个步骤需要记录：

- 当前场景：开书、世界观、角色、大纲、细纲、章纲、正文、审稿、精修。
- 输入要求：用户必须提供什么，系统可自动继承什么。
- 调用资产：底层 Prompt Asset 或 Skill Card。
- 输出产物：方向卡、世界观、角色卡、大纲、章节 brief、正文、审稿报告等。
- 质量门槛：输出不达标时怎么重试。
- 下一步推荐：完成后引导用户做什么。
- 分支变体：例如开书模式/循环模式、主角卡/配角卡、男频/女频书名。

产品规则：

- 新手默认走完整流程。
- 进阶用户可在步骤边界切换别人的节点。
- 正文和精修阶段允许叠加拆书卡、平台包、文风卡。
- 架构设定层不允许无提示地混用多个作者流程。

### 4. Genre / Format Pack

面向题材或平台格式的资产包。

示例：

- 玄幻、修真、都市异能、重生、快穿、末世、悬疑、言情、宫斗宅斗、权谋、电竞、轻小说、追妻火葬场
- 知乎短篇、番茄长篇、老福特、七猫保底、飞卢爽文
- 克苏鲁、宝可梦等强题材定制

产品含义：

- 题材包不一定决定文风，但决定约束和读者预期。
- 题材包应挂在项目上，而不是全局默认。
- 平台格式包应作为用户明确选择后的增强项。

### 4.5 Platform Dimension

发布平台是项目级维度，回答“这本书在哪里竞争”。它不等于题材，也不等于文风。

平台会影响：

- 开篇：前 500 字钩子、前三章承诺、标题简介。
- 章节：单章长度、章尾钩子、爽点/信息密度、更新节奏。
- 审稿：完读、追读、付费节点、情绪密度、题材契合度。
- 资产推荐：推荐番茄平台包、知乎短篇包、老福特关系推进包等。

产品处理：

- 开书前可让用户选择“目标平台”，也可以由 Agent 根据题材、篇幅、文风目标推荐。
- 平台是默认诊断口径，不是硬性写法；用户可关闭商业诊断。
- 平台维度应驱动题材包和流程包推荐，例如“番茄 + 长篇爽文”优先推荐小飞鸡长篇流和番茄钩子包。

### 5. Agent Guide

Agent 不只是执行 prompt，而是负责引导用户少做选择。

Agent 维度建议：

- **开书策划 Agent**：识别用户灵感，推荐题材包/作者流派/脑洞工具。
- **结构规划 Agent**：管理世界观、角色、大纲、章纲、剧情点预算。
- **正文推进 Agent**：根据当前章节状态选择正文、续写、补桥段、改写。
- **主编审稿 Agent**：判断可读性、追读、商业性、逻辑、去 AI 味。
- **资产管家 Agent**：解释当前挂载了哪些 Skill/流程包，提示冲突和缺口。

## 免费 / 付费 / 内置包装

这不是马上定价，而是包装边界。

| 包装 | 来源 | 用户感知 | 使用方式 |
| --- | --- | --- | --- |
| 内置基础能力 | InkFlow 当前 prompt、基础题材 profile | 默认可用 | 不作为商品展示 |
| 免费广场提示词 | `square` 高质量资产 | 可浏览、可试用、可挂载 | 适合做入门 Skill 或流程入口 |
| 付费定制提示词 | 已购买授权的 `private/custom` | 高级流派/题材包 | 白标清洗后可做 Author Flow Pack 或高级 Skill |
| 私有个人资产 | 用户自己上传/购买/导入 | 仅自己可用 | 项目内挂载，不进入公共库 |
| 平台增强包 | 广场/内置/授权资产 | 目标平台适配 | 可免费试用，付费做深度诊断或高级流程 |

PM 判断：

- 免费/付费不要按“单条 prompt”卖，应该按“能完成什么工作流”包装。
- 付费价值应来自连续流程、稳定输出、题材适配和维护更新，而不是神秘提示词文本。
- 任何含作者名、联系方式、私密协议、自我保护话术的内容，必须先白标清洗，再进入付费/免费包装。
- 同类资产比较时，质量更高的已授权定制资产可以替代广场资产成为主版本；未清洗定制资产只能作为候选，不以原文进入产品。

### 质量优先但必须白标

在“世界观/角色/大纲/细纲/正文/润色/审稿”等雷同任务里，不按来源天然排序，而按：

1. `sanitizationStatus`：是否已白标并可进入运行时。
2. 结构质量：变量、步骤、输出、质量门槛。
3. 流程连贯：是否属于当前 Skill Series Flow。
4. 用户目标：平台、题材、长短篇、商业/非商业。
5. 风险：私有化、污染、模板味、不可验证。

结论：

- 已授权且清洗后的定制质量更高时，定制做主版本，广场做免费入口。
- 已授权但未清洗的定制质量更高时，先进入 `sanitize-productize`，清洗后再替代。
- 广场质量足够时，直接做免费 Skill 或流程节点。

## 与现有 InkFlow 的关系

### 现有内置 prompt

当前内置能力包括：

- 灵感助手
- 故事方案卡
- 设定项细化
- 分镜生成
- AI 审计
- 正文生成
- 正文内审
- 拆书萃取
- 全局大纲

这些不应该被外部提示词替换，而应该成为“基础引擎”。外部资产通过三种方式影响它们：

1. **增强基础引擎**：如去 AI 味、对白节拍、剧情点预算。
2. **作为挂载 Skill**：如某作者正文风格、某题材角色生成。
3. **作为流程包路由**：如用户选择“小飞鸡长篇流”后，不同阶段自动切换对应资产。

### Skill 卡与流程包的关系

- Skill Card 是单能力。
- Author Flow Pack 是方法论归属。
- Skill Series Flow 是一组 Skill + Prompt + Agent 路由的可执行流程。
- Genre Pack 是项目约束。
- Agent Guide 是使用时的交互层。

不要把所有东西都压成 Skill 卡。否则流程会被打碎。

## 关键产品原则

1. **用户选目标，不选 prompt**：用户说“我要开一本玄幻长篇”，系统推荐流程包和题材包。
2. **流程包保持连贯**：同一作者流派下的提示词尽量保持原有顺序和方法论。
3. **Skill 可挂载，但不滥挂载**：只有需要长期影响项目的能力才挂载。
4. **Agent 做引导，不做炫技**：Agent 的价值是减少用户选择成本。
5. **题材/文风/平台分离**：玄幻是题材，口语化推进是文风，番茄是发布平台，不能混成一个维度。
6. **免费/付费按结果包装**：卖“长篇开书流程”“短篇爆款流程”“去 AI 味精修包”，不卖一条神秘 prompt。
7. **主归属优先**：雷同提示词先判断主归属，再决定是否抽出通用版。
8. **功能工具不冒充流派**：命名、脑洞、角色、世界观是功能入口，不是作者风格本身。

## MVP 建议

第一版只做三个可验证能力：

1. **流程包识别**：把“小飞鸡长篇流”“风华短篇流”“天马大纲流”整理成 Skill Series Flow。
2. **挂载建议**：在开书/章节页由 Agent 推荐 1 个平台维度 + 1 个流程包 + 1 个题材包 + 1-3 张 Skill。
3. **试驾对比**：同一用户输入下，用内置基础能力 vs 挂载流程包生成对比结果。

暂不做：

- 完整提示词市场
- 复杂价格体系
- 用户自由拼装所有 prompt
- 大规模 UI 改版

## 验收问题

- 用户能否不懂 prompt，也能知道下一步该用什么？
- 同一作者流派是否被保留成连续流程，而不是被拆散？
- 内置 prompt、免费广场、付费定制、私有资产是否边界清楚？
- Agent 推荐是否降低选择成本，而不是增加新概念？
- 题材包、文风包、流程包、Skill 卡是否各司其职？
- 发布平台是否只影响适配和诊断，没有覆盖作者项目设定？
- 世界观/角色/命名等雷同功能是否完成主归属和次归属判断？

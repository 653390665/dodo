# Prompt Deconstruction And Fusion System

日期：2026-07-03
使用技能：`product-strategy-session`、`customer-journey-map`、`prioritization-advisor`、`finance-based-pricing-advisor`

## 核心结论

拆书功能应该从“把一本书萃取成一张文风 Skill”升级为“三类产物”：

1. **拆书报告**：给用户看，解释这本书强在哪里、能学什么、不能学什么。
2. **Deconstruction Skill Cards**：给写作链路叠加使用，如文风卡、节奏卡、钩子卡、爽点卡、反模式卡。
3. **诊断规则**：给审稿、去 AI 味、平台适配使用，如前十章诊断、黄金三章诊断、番茄完读风险。

它不是一个孤立功能，而是连接“外部样本 -> 内部能力卡 -> 写作/审稿/精修”的资产入口。

## 资料判断

现有资料里，拆书强化信号很明确：

| 来源 | 价值 | 建议 |
| --- | --- | --- |
| 小飞鸡长篇拆书器十章版 | 十章级长篇拆解，适合抽节奏、钩子、爽点循环 | 做高级拆书流程候选 |
| 锅盖拆书 | 男频商业拆解，适合节奏和爽点 | 做免费/轻量拆书参考 |
| 猫头鹰短篇拆书 | 短篇结构、反转、情绪线 | 做短篇/知乎/老福特参考 |
| 风华爆款破解/拆文仿写 | 方法论强，用户已确认购买授权 | 白标清洗后可进入短篇/老福特/拆书诊断流程候选 |
| 番茄合集拆书 SOP | 六阶段拆文、黄金三章、单章深拆 | 融合进拆书工厂和平台诊断 |
| webnovel `deconstruction-agent` | 强调可迁移模式、证据、避免污染 | 应作为 `extractSkill` 升级方向 |

结论：定制提示词整体质量通常更高，尤其在流程完整度、质量门槛、商业写作判断上更强。用户已确认购买授权，因此这批定制资产可进入产品化评估；上线前必须白标清洗，去除作者信息、联系方式、个人协议和外部品牌痕迹。同类能力里，高质量定制资产应优先替代普通广场资产作为主版本候选。

## 拆书应拆出的 Skill 卡

拆书不应复制原书设定，而应抽“可迁移写作能力”。建议统一为 12 类卡。

| 卡片 | 拆什么 | 用在哪里 | 是否默认给用户选 |
| --- | --- | --- | --- |
| 主笔文风卡 | 叙述视角、句式密度、用词偏好、对白比例 | 正文、续写、精修 | 可选 |
| 节奏卡 | 章内推进速度、段落长度、信息释放间隔 | 章纲、正文 | Agent 推荐 |
| 钩子悬念卡 | 章首进入、章末悬念、付费点前期待 | 章纲、审稿 | Agent 推荐 |
| 爽点循环卡 | 铺垫、释放、反应、承接的循环 | 大纲、章纲、正文 | Agent 推荐 |
| 角色动力卡 | 欲望、压力、误解、关系拉扯 | 角色、章纲、正文 | Agent 推荐 |
| 对白互动卡 | 对白前因、潜台词、试探、停顿、转移 | 正文、精修 | 可选 |
| 动作链卡 | 人物动作、视线、环境反馈、场面调度 | 正文、去 AI 味 | 默认质量增强 |
| 世界规则模式卡 | 规则、限制、代价、资源结构 | 世界观、大纲 | Agent 推荐 |
| 平台适配卡 | 番茄/知乎/老福特等读者预期 | 开书、审稿 | 选择平台后启用 |
| 反模式卡 | 套路词、拖沓、解释感、崩节奏写法 | 审稿、精修 | 默认质量增强 |
| 主编审稿卡 | 可验证问题、阻断门槛、修复建议 | `manualAudit`、`orchestrateCritic` | 默认质量增强 |
| 连续性提交卡 | 状态变化、伏笔、未闭合问题 | 章节 commit、下一章 brief | 默认质量增强 |

最小可行版本不要一次做 12 张。第一阶段先做：

1. 主笔文风卡
2. 节奏卡
3. 钩子悬念卡
4. 反模式卡
5. 主编审稿卡

## 是否进入评分维度

要进入，但要和“提示词评分”分开。

提示词评分回答：这个 prompt 本身好不好。

拆书卡评分回答：这张卡是否有证据、能否迁移、是否适合当前项目。

### Deconstruction Card Score

总分 100。

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| 证据覆盖 | 20 | 是否有足够章节/片段支撑，而不是凭感觉总结 |
| 信号具体度 | 15 | 是否能落到句式、节奏、钩子、动作等可执行层 |
| 可迁移性 | 15 | 是否抽象为方法，而不是搬原书情节 |
| 污染安全 | 15 | 是否避开角色名、设定名、专属桥段和金句 |
| 项目匹配 | 15 | 是否适合当前题材、平台、篇幅、作者偏好 |
| 可叠加性 | 10 | 是否能与现有 canon、平台包、题材包共存 |
| 可验证性 | 10 | 使用后是否能通过审稿或用户反馈验证 |

### 放置等级

| 等级 | 含义 |
| --- | --- |
| `default-quality-card` | 默认进入审稿/去 AI/动作链，不让用户反复选 |
| `agent-recommended-card` | Agent 在缺节奏、缺钩子、缺角色动力时推荐 |
| `optional-style-card` | 文风、对白、叙述口味，让用户试驾 |
| `project-overlay-card` | 当前作品临时叠加，不全局保存 |
| `saved-skill-card` | 用户确认有效后保存到 Skill 仓库 |
| `premium-diagnostic-card` | 高级拆书、前十章诊断、平台完读诊断 |
| `research-only-card` | 污染风险高、不可验证、或外部来源授权未知，只做内部研究 |

## 融合功能怎么用

融合不是把多个 prompt 拼起来。应有三种融合。

### 1. 默认质量融合

适合后置质量链路。

落点：

- `shared/lib/slop-scorer.ts`
- `shared/lib/rewrite-prompt.ts`
- `shared/config/prompt-templates.ts` 的 `manualAudit`
- `shared/config/prompt-templates.ts` 的 `orchestrateCritic`

使用方式：

- 把去 AI 味、动作链、对白节拍、审稿 schema 融合成默认规则。
- 不改变作者文风。
- 用户最多调“宽松/标准/严格”，不选具体 prompt。

### 2. 运行时叠加融合

适合写作体验链路。

落点：

- `orchestrateWriter`
- 写前 brief
- Skill Stack
- 章节规划

使用方式：

- 主流程仍来自当前作品的流程系列或内置 writer。
- 叠加 1-3 张拆书卡，如“节奏卡 + 钩子卡 + 文风卡”。
- 卡片只影响表达、节奏、兑现方式，不改 canon。
- 每章可开关，避免用户被长期绑死。

### 3. 显式 Skill 融合

适合 Skill Studio / Fusion Workbench。

使用方式：

- 一张主卡 + 一张支持卡。
- 系统输出：保留什么、吸收什么、冲突什么、风险什么。
- 先作为 `project-overlay-card` 试用。
- 连续 2-3 次用户接受后，才推荐保存成新版 Skill。

原则：融合要有证据、有回滚、有试驾，不直接覆盖原 Skill。

## 现有功能如何强化

| 现有功能 | 当前定位 | 强化方向 |
| --- | --- | --- |
| `extractSkill` | 拆书萃取 | 从单张文风卡升级为多卡 deck：文风、节奏、钩子、反模式、审稿卡 |
| `buildSkillDeckFromEvidence` | 证据聚合 | 增加卡片类型、证据覆盖分、污染风险、推荐放置 |
| Book Factory | 上传/拆书入口 | 拆成“报告 / 生成卡组 / 诊断对标”三种意图 |
| Skill Studio | 管理 Skill | 展示来源、证据、稳定性、适用阶段、融合建议 |
| `orchestrateWriter` | 正文生成 | 只接收被选中的 overlay 卡，通过 brief 收窄，不吃全量资产 |
| `manualAudit` | 审稿 | 默认吸收审稿卡、反模式卡、平台轻诊断 |
| `orchestrateCritic` | 主编内审 | 做 blocking 判断，输出可验证问题，不做泛泛评分 |
| `slop-scorer` | 去 AI 味扫描 | 吸收反模式卡、动作链卡、对白节拍，减少解释感和机械收尾 |
| `buildRewritePrompt` | 精修重写 | 使用质量卡做局部补丁，不整章重写，不改剧情顺序 |

## 交互流程是否要调整

要调。拆书入口不能再只问“上传哪本书”，而要先问用户目的。

### 新拆书旅程

1. **选择目的**
   - 学文风
   - 学节奏/钩子
   - 做平台对标
   - 做前十章诊断
   - 生成可挂载卡组

2. **系统拆成卡组**
   - 主笔文风卡
   - 2-4 张支持卡
   - 风险卡
   - 推荐使用位置

3. **用户选择使用方式**
   - 只看报告
   - 临时叠加到当前作品
   - 保存到 Skill 仓库
   - 进入融合工坊
   - 对当前章节/前十章做诊断

4. **进入写作链路**
   - 开书阶段：推荐世界规则模式卡、角色动力卡。
   - 章纲阶段：推荐节奏卡、钩子卡、爽点循环卡。
   - 正文阶段：推荐文风卡、对白卡、动作链卡。
   - 审稿阶段：默认启用反模式卡、主编审稿卡、平台适配卡。

5. **反馈回收**
   - 用户接受/拒绝卡片影响。
   - 连续有效才推荐保存或融合。
   - 低分卡自动降权，不打扰用户。

### 降低选择困惑

用户不应该看到 12 类卡和 140 条 prompt。

UI 应只说：

- “这本书最值得学的是：节奏和章末钩子。”
- “建议临时挂到：第 1-10 章章纲。”
- “风险：不建议学习它的具体设定和人物关系。”
- “可选动作：试用到下一章 / 只做报告 / 保存为卡片。”

## 工作流是一路到底还是可切换

建议：架构层默认连贯，写作层允许切换。

### 不建议切换的地方

- 世界观刚生成到一半。
- 主角设定已经写入 canon 后，又用另一个流程重写主角底层动机。
- 大纲主承诺已确定后，用另一套流程改作品类型。

### 允许切换的地方

- 开书前：自由切换流程、平台、题材。
- 世界观完成后：可换大纲工具，但必须继承世界观。
- 大纲完成后：可换细纲/章纲工具，但不能改核心承诺。
- 章纲完成后：可换正文风格、拆书卡、对白/动作卡。
- 正文完成后：可换审稿/精修/平台诊断。

### 用户为什么会切换

- 架构流强，但正文不好看。
- 正文风格好，但章末钩子弱。
- 商业平台目标变了。
- 当前章节卡文，需要专项拆书卡救场。
- 免费流程能用，但想升级为更稳定的付费流程。

## 通用、付费、内置怎么分

### 免费内置

这些是软件质量，不应作为付费墙前的基本缺口：

- 基础拆书报告。
- 一张主笔文风卡 + 两张支持卡。
- 基础去 AI 味。
- 基础审稿。
- 基础脑洞、取名、简介。
- 基础世界观/角色引导。

### 付费增强

这些能显著降低长篇失败率，适合收费：

- 前十章深度拆解。
- 黄金三章诊断。
- 平台完读/付费点诊断。
- 高级拆书卡组。
- 多书对标卡组。
- 作者流程包，如小飞鸡长篇流。
- Skill Fusion Workbench。
- 长篇连续性 commit 和剧情点预算。

### 白标清洗 / 研究-only

这些不能以原文直接用户可见：

- 未清洗的定制提示词原文。
- 含作者名、个人保护协议、联系方式、强私有化身份的 prompt。
- 容易复制原书设定/情节/金句的拆书结果。

清洗后仍污染高、不可验证或质量不稳的资产，才进入 `research-only` 或 `reject`。

## 盈利判断

不要按单条提示词卖。用户真正愿意付费的是：

- 少走弯路。
- 第一章更能看。
- 前十章不塌。
- 审稿能指出具体问题。
- 卡文时知道下一步做什么。
- 学会某类风格，但不侵权、不跑偏。

建议包装：

| 套餐 | 内容 | 用户感知 |
| --- | --- | --- |
| 免费 | 基础开书、基础拆书、基础审稿、基础去 AI | 能完成第一章闭环 |
| Pro | 高级拆书卡组、平台诊断、Skill Stack、去 AI 严审 | 作品质量更稳 |
| Studio | 作者流程包、前十章诊断、多书对标、融合工坊 | 长篇/商业化创作者 |
| 定制 | 授权定制提示词、专属流程、私有卡库 | 专业作者/工作室 |

## 优先级建议

按 impact / confidence / effort 判断，先做下面 5 件。

1. **拆书卡分类和评分 schema**
   - 影响：高
   - 信心：高
   - 成本：中
   - 原因：没有统一卡片，后面融合都会乱。

2. **`extractSkill` 多卡 deck 输出**
   - 影响：高
   - 信心：中高
   - 成本：中
   - 原因：直接强化已有拆书入口。

3. **后置质量默认融合**
   - 影响：高
   - 信心：高
   - 成本：低中
   - 原因：审稿/去 AI 味是软件质量线，用户不需要选择。

4. **章节写作 overlay 卡**
   - 影响：中高
   - 信心：中
   - 成本：中
   - 原因：能体现差异化，但要防止风格互相打架。

5. **高级拆书和平台诊断付费包**
   - 影响：中高
   - 信心：中
   - 成本：中高
   - 原因：商业价值清晰，但需要先验证输出稳定。

## 验收标准

- 拆书结果至少能输出：主笔文风卡、节奏卡、钩子卡、反模式卡。
- 每张卡都有证据覆盖、污染风险、推荐放置、适用阶段。
- 拆书卡不包含原书角色名、地名、组织名、能力名、金句。
- 用户默认不看到复杂卡片体系，只看到推荐动作。
- `manualAudit` / `slop-scorer` / `buildRewritePrompt` 能默认使用质量卡。
- `orchestrateWriter` 只使用用户确认或 Agent 推荐的少量 overlay 卡。
- 高级拆书付费能力必须能证明比免费版多出“诊断深度”或“长篇稳定性”，不能只是多给几条总结。

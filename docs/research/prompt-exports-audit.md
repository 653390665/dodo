# Prompt Exports Audit

评估日期：2026-07-03
来源目录：`/Users/Zhuanz/Documents/codex/2026-07-03/ni-k/outputs/all_prompt_exports`

## 结论

这批 140 条提示词不应该只被压进 InkFlow 现有六阶段。更好的用法是把它当成一次外部创作工序审计：既评估哪些提示词能补强现有模块，也评估现有模块、维度和流程是否需要被它们反向修正。

产品判断：本次工作的核心不是“提示词导入”，而是“学习型创作系统升级”。如果一条高质量提示词呈现出更好的流程、维度或写作判断，InkFlow 应该允许自身体系演进，而不是为了贴合旧架构切碎它。

建议第一阶段不改运行时提示词，只形成候选池与接入路线。优先级最高的是三类：

1. **文风/去 AI 味**：对 `orchestrateWriter`、`buildRewritePrompt`、`slop-scorer` 有直接补强价值。
2. **长篇规划/细纲**：对 `generateOutline`、`editorAgent` 和章节生产流程有流程级补强价值。
3. **拆书/审稿**：对 `extractSkill`、`manualAudit`、`orchestrateCritic` 有评估维度补强价值。

## 评估原则

### 产品目标

本轮评估服务三个 outcome：

1. **提升生成稿可读性**：减少 AI 腔、解释感、模板化动作和机械句式。
2. **提升长篇稳定性**：让章节生产不提前透支剧情点，能支撑多章循环。
3. **提升体系学习能力**：让外部高质量提示词反向升级 InkFlow 的阶段、维度和流程。

### 双向适配

现有 InkFlow 维度是初始坐标，不是裁剪刀。评估时允许三种结果：

1. 外部提示词适配现有模块：直接沿用或融合进已有提示词。
2. 外部提示词暴露现有维度缺口：调整 InkFlow 的评估轴、阶段或流程。
3. 外部提示词与主线冲突：保留为研究样本，不接入。

因此，`discovery / foundation / planning / drafting / polish / review` 只用于定位，不用于强行切割内容。比如一条“长篇细纲”提示词可能同时改变 `generateOutline`、`editorAgent`、章节生产循环和伏笔账本。

PM 取舍：如果“保护现有架构”和“吸收高质量流程”冲突，优先保护用户主线体验，其次保护提示词的完整创作逻辑，最后才保护现有内部分类。

### 处理结论

| 结论 | 使用条件 | 进入方式 |
| --- | --- | --- |
| `direct-use` | 结构稳定、变量清楚、输出可控、已白标清洗 | 小范围直接挂接或作为可选内部模板 |
| `fuse` | 与现有提示词互补，但不适合整段替换 | 合并规则、流程、检查项 |
| `extract-structure` | 工序强，表达冗长或私有化过重 | 只取流程、变量、质量门槛 |
| `style-reference` | 能明显改善文风、去 AI 味、对白、动作链 | 补 `slop-scorer`、改写提示、写作自检 |
| `system-upgrade` | 反向指出 InkFlow 当前阶段或维度不够 | 调整产品流程或新增内部评价维度 |
| `reject` | 污染大、不可验证、模板味重、白标后仍不可控 | 仅记录淘汰原因 |

## 关键发现

### 1. InkFlow 当前缺“流程跨度”

现有 PromptStage 更像单次调用阶段。外部高质量长篇提示词往往以“十章循环”“黄金三章”“剧情点消耗清单”“分次生成”组织流程。它们不只补某个 prompt，而是提示 InkFlow 需要一个跨章节生产节拍：

- 开书模式：前 1-10 章立住小说。
- 循环模式：第 11 章后按 10 章为单位规划差异化推进。
- 时间线约束：当前章节只能消耗当前区间及之前的剧情点。
- 伏笔允许提前出现，但不能提前解释。

这说明 `planning` 不应只等于“生成当前章节分镜”，还需要一个“剧情点预算/消耗”层。

### 2. 去 AI 味不是禁词表而是写作机制

`slop-scorer` 已能扫 AI 套话、陈词、tell-dont-show、句长单一。但外部优质润色提示词补充了更完整的机制：

- 用动作、场景线索、可观察反应替代心理解释。
- 控制标点、连接词、弱动词和模板化表情。
- 大段对白必须被动作节拍打断。
- 每段改写保留原剧情与设定，不为了去 AI 味牺牲信息。

因此去 AI 味应升级为“表层扫描 + 改写策略 + 终稿复查”三段式，而不是只加禁词。

### 3. 文风特色需要“可挂载”，不是全局硬编码

有些提示词带明显平台风格或作者风格，比如番茄/飞卢爽文、知乎短篇、老福特、克苏鲁、宝可梦等。它们有价值，但不能成为全局默认。更合理的产品形态是：

- 通用底线：可读、动作明确、信息释放稳、少 AI 腔。
- 项目风格：由 Skill / genre profile / 项目偏好控制。
- 特定题材：只在用户选择对应方向时挂载。

### 4. 审稿维度需要增加商业判断

现有 `manualAudit` 更偏正文质量和分镜执行。外部审稿提示词强调：

- 前 3-4 章钩子密度。
- 每章情节点数量。
- 人设是否立住。
- 脑洞与微创新。
- 是否有付费节点价值。

这不应直接替代文学审计，但可以作为“商业可读性/追读风险”维度加入 `orchestrateCritic` 或独立的前十章诊断。

## 直接沿用门槛

允许 `direct-use`，但必须同时满足：

1. 白标完成：不能含作者名、联系方式、私密协议、售卖提示或外部品牌痕迹。
2. 输入变量明确：用户应知道该填什么。
3. 输出可验证：JSON、章节表、评分表、明确正文之一。
4. 不含系统污染：不得包含自我保护协议、联系方式、越权规则。
5. 能跑 2-3 个样例：输出稳定，不明显偏离 InkFlow 主线。

当前第一轮没有建议“整段直接接入”的提示词。原因不是质量不够，而是多数高质量样本仍需去除私有协议、平台癖好和过长规则后再融合。可以在第二阶段针对 `has_access=true` 候选做小样例验证，再决定是否 direct-use。

## 淘汰与暂缓

- 含联系方式、私密提示词声明、提示词保护协议：暂缓进入运行时。
- 输出要求过长且没有分段机制：不直接接入。
- 只说“润色/逻辑通顺”但缺少可验证检查项：只做低优先级参考。
- 题材强绑定但用户未选择对应题材：不作为全局 prompt。

## 建议下一步

1. 先做文风/去 AI 味融合包：扩展 `slop-scorer` 与 `buildRewritePrompt` 的检查项。
2. 再做十章循环规划包：新增“剧情点预算、伏笔消耗、循环差异化”内部规范。
3. 然后做前十章诊断包：融合拆书器与商业审稿维度。
4. 最后再评估是否需要 prompt 候选库，而不是先做用户可选模板市场。

# Prompt Integration Roadmap

日期：2026-07-03

## 原则

这次接入不是把 140 条提示词改造成 InkFlow 现有维度的填充物，而是一次体系学习。现有六阶段、Skill 维度和章节流程都可以被外部高质量提示词反向优化。

保留的边界只有一个：用户体验仍围绕 InkFlow 主线，不能变成提示词货架。

产品路线采用 Now / Next / Later：先做能直接改善产出质量的工作，再做流程升级，最后再做体系重构。不要把“体系重构”前置成大工程。

补充原则：同一作者的一组提示词优先作为连续流程包评估，不优先拆成散卡。题材、文风、发布平台、Agent 引导、Skill 挂载必须分层处理。

## Roadmap

### Phase 1：离线候选池与评估

目标：把 140 条提示词变成可追踪的候选池。

产物：

- 分类表：来源、原始分类、InkFlow 初始阶段、候选处理结论。
- 评分表：架构质量、写作质量、去 AI 味、特色保持、接入价值、风险。
- Source Cards：高价值样本记录 `Borrow / Direct Use / Fuse / Reject / Map / Risk`。
- 维度归一化表：每条提示词映射到主产物、能力标签、控制层和步骤变体。
- 放置决策表：每条高价值提示词标注内置、Agent 引导、选配、付费、白标清洗或 research-only。

验收：

- 总数覆盖 140。
- `square/private/creative` 三类都覆盖。
- 用户已确认购买授权，`has_access=false` 不再作为授权阻断；但未白标清洗的原文不进入 `direct-use`。
- 每个 Top 候选都有映射模块、白标要求和风险说明。
- 同类资产要标注“是否由清洗后的高质量定制替代广场”。
- 复合提示词必须拆出 Capability Unit，不能把脑洞+世界观+正文混成一张用户可见 Skill。
- 后置质量链路默认内置强化，前置基础质量工具由 Agent 引导，正文风格保持选配。

### Phase 2：文风与去 AI 味补强

目标：先补最能直接改善产出质量的层。

建议改动：

- `slop-scorer`：
  - 增加弱动词、模板表情、标点过密、解释感句式。
  - 把命中项分成硬禁、强替、弱替，减少误伤。
- `buildRewritePrompt`：
  - 加入“镜头感替代解释感”。
  - 加入“时间线、情绪线、信息线”精修策略。
  - 加入对白动作节拍和 POV 连续性检查。
- `orchestrateWriter`：
  - 生成正文前明确项目风格，生成后做轻量自检。
  - 把去 AI 味作为写作机制，不只是修稿机制。

验收：

- 用 2-3 段现有章节样本文本做前后对比。
- `slop-scorer` 命中率提升，但不把正常作者风格大量误报。
- 改写后不改变剧情顺序、设定、悬念落点。

### Phase 2.5：资产模型与交互引导

目标：明确用户如何理解和使用 Prompt、Skill、流程包、题材包、Agent。

建议改动：

- 建立资产层级：
  - Prompt Asset：原始提示词和清洗候选。
  - Skill Card：可挂载的单能力。
  - Author Flow Pack：同作者/同方法论连续流程。
  - Skill Series Flow：可执行步骤、步骤变体、质检门槛、下一步推荐。
  - Genre / Format Pack：题材、平台格式和读者预期。
  - Platform Dimension：目标发布平台、商业规则和章节交付口径。
  - Agent Guide：按当前阶段推荐下一步。
- 用户交互：
  - 开书时推荐目标平台、流程包和题材包。
  - 章节规划时推荐章纲/细纲/剧情点预算能力。
  - 正文后推荐审稿/去 AI 味能力。
  - 资产库只作为次级入口，不作为主流程。

验收：

- 用户不需要浏览 140 条 prompt 也能获得推荐。
- 同一作者流程不被拆散。
- 同一流程内的多分支能成为 Step Variant，而不是散成一堆 Skill。
- 用户能看到当前挂载了什么、为什么挂载、如何关闭。
- 平台维度能影响诊断和推荐，但不强行覆盖作者文风。

### Phase 3：长篇规划流程升级

目标：把“单章分镜”升级为“跨章节剧情预算”。

建议改动：

- `generateOutline`：
  - 增加核心卖点、金手指限制、阶段目标、章节比例。
  - 支持长大纲分次生成，而不是一次性吐完。
- `editorAgent`：
  - 生成当前章分镜前，先识别当前章节可用剧情点。
  - 区分伏笔暗示和剧情提前消耗。
- 章节生产流程：
  - 增加剧情点消耗清单。
  - 前十章使用“开书模式”，后续使用“循环模式”。
  - 每个循环要求冲突类型、悬念类型或节奏控制至少有一处变化。

验收：

- 不提前消耗后续章节关键真相。
- 分镜能说明本章使用了哪些剧情点。
- 后续章节仍有内容可写，不因前文透支而塌陷。

### Phase 4：前十章诊断与商业审稿

目标：补现有审稿维度缺少的“追读/商业可读性”。

建议改动：

- 新增内部诊断能力，不默认打断写作流。
- 诊断项：
  - 前三章钩子是否成立。
  - 每章核心功能是否明确。
  - 主角驱动力、障碍、金手指限制是否立住。
  - 伏笔和读者期待是否持续。
  - 是否有脑洞微创新和付费节点潜力。
- `manualAudit` 和 `orchestrateCritic` 只吸收可执行检查项，不吸收编辑人设表演。

验收：

- 输出必须给章节级建议。
- 建议必须可执行，不能只说“节奏不够紧凑”。
- 商业判断不能覆盖作者选择，必须标明“适合商业爽文时启用”。

### Phase 5：学习型体系与维度重构

目标：根据评估结果反向优化 InkFlow，而不是守旧。

候选体系调整：

- 在六阶段之外新增内部横轴：
  - `cross-chapter-continuity`：跨章连续性、剧情点预算、伏笔消耗。
  - `style-humanization`：去 AI 味、动作化、POV、对白节拍。
  - `commercial-readability`：追读、钩子、付费节点、题材卖点。
  - `genre-fit`：题材规则、平台风格、项目偏好。
  - `platform-fit`：目标平台、章节长度、开篇承诺、完读/追读/付费规则。
- Skill 维度从固定六项扩展为可组合：
  - 保留 `style / character / world / power / plot / pacing`。
  - 允许增加项目级标签，如 `dialogue`, `hook`, `suspense`, `commercial`, `anti-ai`.

验收：

- 新维度不能强迫所有项目使用。
- 每个维度都必须能映射到具体生成或审稿行为。
- UI 不暴露复杂度，复杂度留在内部路由和候选挂载。

PM 判断：

- 不是为了“维度更多”而扩展维度。
- 只有当某个新维度能稳定改善生成、审稿或作者决策时，才进入产品体系。
- 如果外部提示词暴露出更好的工作流，优先把它做成内部能力，不急着做用户可见入口。

## 不做什么

- 不把 140 条提示词做成用户可见模板市场。
- 不把外部平台风格设为全局默认。
- 不强迫每本书先选平台；不确定时允许“通用长篇/通用短篇”。
- 不把未白标清洗的原始定制提示词接入运行时。
- 不为了符合当前架构而切割高质量提示词。
- 不为了“去 AI 味”牺牲作者个人文风。

## 推荐实施顺序

1. 文风/去 AI 味：收益最大，风险可控。
2. 拆书卡组 schema：先统一文风、节奏、钩子、反模式、审稿卡，避免后续融合对象混乱。
3. 长篇规划流程：能改善章节生产稳定性。
4. 资产模型与交互引导：防止功能越做越乱。
5. 前十章诊断：适合做主动触发工具。
6. 题材 profile 补强：逐步补，不急。
7. 体系重构：等前面有实证后再改类型和 UI。

## 后续实现提示

如果进入代码实现，优先做小步：

1. 先扩展 `slop-scorer` 的检测项和测试。
2. 再定义拆书卡组 schema，并让 `extractSkill` 输出多卡 deck。
3. 再调整 `buildRewritePrompt` 的精修规则。
4. 再更新 `orchestrateWriter` 和 `manualAudit` 的提示词。
5. 最后再考虑数据结构和 UI。

每一步都要用真实章节样本验证，不靠“看起来更专业”判断成功。

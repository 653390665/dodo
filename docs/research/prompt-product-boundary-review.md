# Prompt Product Boundary Review

日期：2026-07-03
使用技能：`product-strategy-session`、`problem-framing-canvas`、`customer-journey-map`、`prioritization-advisor`

## 核心判断

当前规划方向正确，但必须收敛成一句产品原则：

**提示词资产不成为用户入口；它们成为 Agent 背后的能力、流程和质量护栏。**

如果把提示词直接做成模板市场，会造成选择负担、功能重复和文风污染。正确做法是：

- 用户面对的是“我要开书 / 写章 / 审稿 / 精修 / 卡文”。
- Agent 判断当前阶段、项目画像和缺口。
- 系统在后台调用内置 prompt、白标定制资产、广场资产、拆书卡或流程包。
- 用户最多看到 3 个下一步动作，而不是看到 140 条提示词。

## 重新框定问题

### 原始问题

我们有大量高质量提示词，不知道怎么使用。

### 真实问题

作者不是缺提示词，而是缺一条低负担、可持续、能保持风格的写作推进链路。

问题可以表述为：

> 网文作者在 AI 辅助写作中，容易在开书、架构、写章、审稿、精修之间反复切换工具，因为资产没有被编排成阶段化能力，导致选择过多、质量不稳、文风漂移和长篇连续性不足。

How Might We：

> 如何让 InkFlow 在不暴露复杂提示词库的前提下，把高质量提示词变成当前阶段的下一步建议、默认质量护栏和可选风格增强？

## 功能边界调整

### 一、不能新增“提示词市场”作为主入口

不做：

- 140 条 prompt 列表。
- 用户手动挑作者、题材、平台、审稿、文风组合。
- 按单条提示词售卖。

要做：

- 资产库作为次级入口。
- 主入口仍是创作任务。
- Agent 按当前缺口推荐能力。

### 二、现有功能不替换，只增强

| 现有功能 | 不做什么 | 增强什么 |
| --- | --- | --- |
| 灵感 / 开书 | 不变成提示词选择页 | 增加平台、题材、流程建议 |
| Book Factory / 拆书 | 不只生成一张文风 Skill | 生成报告、卡组、诊断规则 |
| Skill Studio | 不堆原始 prompt | 管理白标 Skill、证据、版本、融合 |
| Editor / 章纲 | 不让用户选章纲 prompt | 按流程/平台/剧情点预算增强 |
| Writer / 正文 | 不吃全量资产 | 只接收写前 brief 和少量 overlay 卡 |
| Audit / Polish | 不做可选审稿货架 | 默认融合审稿、反模式、去 AI 规则 |

### 三、质量护栏和写作体验必须分开

默认内置：

- 审稿 blocking。
- 去 AI 味。
- 动作链。
- 连续性。
- 反模式。
- 输出结构校验。

用户选配：

- 作者正文风格。
- 拆书文风卡。
- 平台强风格。
- 对白/节奏/钩子专项卡。

原因：质量护栏是软件能力，不能让用户反复选择；文风是创作体验，必须保留选择权。

## 维度是否完整

现有规划的三层维度是正确的：

1. **产物维度**：这一步产出什么。
2. **能力维度**：这条资产改善什么。
3. **控制层维度**：它能不能随便切换或叠加。

需要补强两个判断：

- `platform` 不是题材，也不是文风；它是项目级诊断口径。
- `authorSeries` 不是 Skill；它是流程编排来源。

第一阶段维度建议固定为：

| 层 | 必须支持 | 暂缓 |
| --- | --- | --- |
| 产物 | `ideaSeed/titleSynopsis/worldBible/characterCard/powerSystem/plotOutline/detailedOutline/chapterPlan/writingBrief/draft/reviewReport/polishPatch/skillCard` | 更细的营销物料 |
| 能力 | `styleVoice/pacing/hook/dialogue/actionChain/emotionTension/payoffLoop/antiAI/continuity/commercialReadability` | 过细的个人癖好标签 |
| 控制层 | `canon/flow/overlay/diagnostic/utility` | 多层继承和复杂权限 |

## 流程链路修正

主链路应固定为：

`开书意图 -> 项目画像 -> 流程推荐 -> canon 架构 -> 章节循环 -> 写前 brief -> 正文 -> 审稿/去 AI -> 状态 commit -> 下一步推荐`

拆书不是必经主链，而是三类入口：

- **参考入口**：开书前对标爆款，抽节奏和钩子。
- **救场入口**：写作中卡文，临时叠加专项卡。
- **诊断入口**：写完后对照平台和样本做前十章/黄金三章诊断。

作者流程不是必须一路到底：

- 架构层默认连贯，切换需一致性检查。
- 正文和精修层允许按章切换或叠加。
- 审稿层可并行，但输出必须可执行。

## 优先级重排

基于 impact / confidence / effort，建议从原来的“先做去 AI”调整为：

1. **边界与白标清洗规则**
   - 先统一已授权定制资产的可用条件。
   - 产物：白标字段、清洗规则、用户不可见来源策略。

2. **拆书卡 schema 与评分**
   - 先统一卡片形态，避免后续融合对象混乱。
   - 产物：5 类 MVP 卡、证据分、污染风险、推荐放置。

3. **后置质量链路增强**
   - 审稿、去 AI、动作链、反模式默认内置。
   - 产物：`slop-scorer`、`manualAudit`、`buildRewritePrompt` 的规则增强。

4. **写前 brief 与正文 overlay**
   - 正文只吃少量被选中的增强卡。
   - 产物：Writer 上下文收窄，不让 prompt 堆叠污染正文。

5. **作者流程包 MVP**
   - 先做小飞鸡长篇流、风华短篇/老福特流、天马大纲流。
   - 产物：Skill Series Flow + Step Variant。

6. **平台与前十章诊断**
   - 选择平台或商业模式后启用。
   - 产物：番茄/知乎/老福特等诊断口径。

## 需要删除或降级的想法

删除：

- 公开提示词市场。
- 单条 prompt 付费。
- 所有项目默认平台化。
- 让用户每章手动选择一堆 Skill。

降级为后台能力：

- 140 条资产列表。
- 复杂评分维度。
- 白标来源记录。
- 权限/授权台账。
- Agent 路由规则。

保留为用户可见：

- 当前作品使用的流程。
- 当前挂载的增强包。
- 推荐原因。
- 可关闭/可替换动作。
- 试驾结果。

## 验收标准

规划正确的判断标准不是“资产都被用上”，而是：

- 用户无需浏览提示词列表，也能完成开书到首章。
- 审稿和去 AI 默认更强，但不改变作者文风。
- 拆书结果能明确告诉用户“学什么、不学什么、用在哪里”。
- 同类提示词被归并为主版本、免费入口、流程节点或后台规则，而不是重复功能。
- 作者流程能保持连贯，同时允许在步骤边界切换。
- 平台规则只在用户选择平台或商业诊断时增强，不强迫所有作品商业化。

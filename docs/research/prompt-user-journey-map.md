# Prompt Asset User Journey Map

日期：2026-07-03
使用技能：`customer-journey-map`

## Persona

**网文作者 / AI 辅助创作者**

目标：从一个想法推进到可持续连载的章节产出，同时保留自己的文风，不被 AI 味和复杂工具打断。

## Journey Objectives

- 让用户少选 prompt，多做创作决策。
- 在关键节点给出“下一步推荐”，而不是把资产库推给用户。
- 把作者流程包、题材包、Skill 卡、Agent 引导组合成一条清晰路径。

## Journey Map

| Stage | 用户动作 | 触点 | 用户心理 | 系统引导 | KPI |
| --- | --- | --- | --- | --- | --- |
| 1. 灵感输入 | 写一句想法、题材、梗 | Welcome / 灵感助手 | “我想写，但还没成型” | 推荐 2-3 个方向；提示可选题材包/作者流程包 | 方案卡选择率、澄清次数 |
| 2. 选择创作路线 | 选择长篇/短篇/目标平台/作者流派 | 方案卡 + 流程推荐 | “我不知道在哪发、用哪套流程适合我” | Agent 推荐：目标平台 / 内置基础流 / 免费广场流 / 定制流 | 推荐接受率、跳出率 |
| 3. 建立骨架 | 生成世界观、角色、金手指、大纲 | Book Factory / World Bible | “别让我填太多表” | 按流程包逐步补齐；只问当前必须决策 | 骨架完成率、字段返工率 |
| 4. 章节规划 | 生成细纲、章纲、剧情点预算 | Editor / Planning | “这一章该写什么” | 识别当前可用剧情点；提醒伏笔不可提前揭示 | 分镜接受率、提前透支告警 |
| 5. 正文生成 | 生成或续写当前章 | Writing Surface | “要像我想要的文风” | 自动挂载项目 Skill、题材包、流程包正文资产 | 正文接受率、重写次数 |
| 6. 精修去 AI 味 | 修对白、动作链、解释感、模板词 | Audit / Polish | “这段像 AI，帮我修人一点” | 主编 Agent 给出可执行问题；一键手术式修补 | 去 AI 味命中下降、用户采纳率 |
| 7. 流程学习 | 保存偏好、反馈好坏、融合 Skill | Skill Studio | “这套写法越来越懂我” | 推荐固定挂载/替换/融合；形成项目流派 | Skill 留存率、反馈率 |
| 8. 资产扩展 | 浏览广场/付费/私有提示词 | Asset Library | “我想找更适合题材的工具” | 按当前项目缺口推荐，不展示大杂烩 | 试驾率、购买/安装转化 |

## Interaction Principles

### 1. 默认不让用户选 prompt

用户入口应该是：

- 我要开书
- 我要补角色
- 我要生成章纲
- 我要写正文
- 我要去 AI 味
- 我要审稿

系统再决定调用哪条 prompt、哪个 Skill、哪个流程包。

### 2. 资产推荐必须有理由

推荐文案不说“这里有 12 条提示词”，而说：

- “你现在缺的是前十章节奏，这套流程能先做剧情点预算。”
- “这章对白多，建议挂载对话情绪拉扯增强。”
- “你选择的是克苏鲁题材，世界观和正文规则需要一起挂载。”
- “你已选择小飞鸡长篇流，世界观会优先使用这套流程里的世界观节点；也可以切换为通用世界观工具。”
- “你现在更像番茄长篇，建议启用章首章末钩子和完读诊断；如果想走晋江，重点会转向关系推进和文案承诺。”

### 3. 流程包只在关键时刻出现

适合出现：

- 开书时：选择作者流派/题材格式。
- 章节卡住时：推荐某个流程节点。
- 审稿后：推荐对应改稿包。
- 一个流程步骤完成时：提示下一步，而不是展示全部提示词。

不适合出现：

- 每次生成正文前都让用户手动选。
- 设置页里堆出 140 条 prompt。

### 4. Agent 用“下一步”语言

Agent 不应像设置面板，而应像主编：

- “这本书现在骨架不稳，先补主角驱动力。”
- “第 1-3 章不能提前揭示第 20 章真相，我会只埋伏笔。”
- “这段 AI 味主要来自解释感和模板表情，我建议局部手术，不重写整章。”

### 5. 免费/付费不要打断创作

付费提示应出现在用户感到明确缺口时：

- 用户多次使用某个免费流程并接受结果。
- 用户正在写强题材，需要高级题材包。
- 用户明确想模仿某类作者流程。

不应在开书第一屏推销。

### 6. 雷同功能要解释来源

同样是“生成世界观/角色/大纲”，用户不需要看到所有同名工具。系统只给三种解释：

- “流程内推荐”：来自你当前选择的作者流程。
- “通用工具”：跨题材可用，适合快速补材料。
- “题材专用”：专为克苏鲁、宝可梦、老福特等格式设计。

这样用户知道自己是在延续流程、调用通用功能，还是切换题材专用工具。

### 7. 工作流切换必须发生在步骤边界

用户可以切换，但系统要解释代价：

- 架构层切换：会影响 canon，需要一致性检查。
- 写作层切换：只影响表达和节奏，可试驾对比。
- 审稿层切换：只影响诊断口径，可多路并行。

默认文案：

- “这一步可以换成天马大纲，但会继续沿用你已生成的世界观和主角设定。”
- “正文风格可以临时叠加锅盖男频卡，不会修改大纲。”
- “你现在启用番茄诊断，我只检查完读和钩子，不会强迫改成番茄文风。”

## Key Pain Points & Opportunities

### Pain Point 1：资产过多导致选择瘫痪

Opportunity：用 Agent 根据当前阶段推荐最多 3 个选项。

### Pain Point 2：作者流程被拆散

Opportunity：把同作者提示词聚合为 Author Flow Pack，保留顺序、适用场景和连贯风格。

### Pain Point 3：题材、文风、发布平台混在一起

Opportunity：交互上分三层：

- 题材：写什么世界。
- 文风：怎么写句子和场景。
- 平台：在哪里发布、按什么读者预期和商业规则优化。

平台选择不必强制先填。Agent 可以用四个问题推断：

- 目标篇幅：短篇、十万字、百万字长篇。
- 读者目标：追读、付费、同人互动、口碑沉淀。
- 节奏偏好：快节奏爽点、慢热沉浸、关系拉扯、反转压缩。
- 变现目标：免费流量、订阅、保底、私域/同人圈层。

### Pain Point 4：用户不知道 Skill 何时挂载

Opportunity：引入“挂载建议”而不是“自由选择”。系统说明挂载原因、影响范围和可撤销性。

### Pain Point 5：内置能力与外部资产关系不清

Opportunity：把内置能力称为“基础引擎”，外部资产称为“增强包”。用户只需要理解增强包会改变哪些结果。

## First-Slice Interaction

MVP 只做一条完整路径：

1. 用户输入灵感。
2. 系统生成方向卡。
3. Agent 推荐一个目标平台、一个流程包和一个题材包。
4. 用户接受或跳过。
5. 系统生成骨架和首章规划。
6. 用户生成正文。
7. 审稿后推荐去 AI 味 Skill。

验收：

- 用户全程不需要打开提示词列表。
- 用户能看到当前挂载了什么，以及为什么。
- 用户可以随时关闭某个增强包。

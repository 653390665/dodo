# Prompt Workflow Product System

日期：2026-07-03
使用技能：`product-strategy-session`、`roadmap-planning`、`customer-journey-map`、`finance-based-pricing-advisor`

## 核心结论

这批提示词不能只做“导入模板库”。它们暴露的是一套更大的产品系统：

`创作目标 -> 平台/篇幅/题材判断 -> 流程系列选择 -> 架构设定 -> 章节循环 -> 写前 brief -> 正文生成 -> 审稿 commit -> 精修去 AI 味 -> 偏好学习`

单条 Prompt 只是原料。真正的产品形态应该是：

1. **Skill Series Flow**：连续流程，带步骤、变体、质量门槛和下一步引导。
2. **Flow Step Variant**：同一步里的分支模式，例如开书模式/循环模式、主角卡/配角卡、男频/女频书名。
3. **Skill Stack**：正文写作和精修阶段允许叠加拆书卡、平台包、题材包、文风卡。
4. **Agent Orchestrator**：判断用户当前处境，推荐平台、流程、下一步和可切换节点。

- 小飞鸡角色卡：主角/重要配角 / 次要配角。

产品判断：多分支提示词不应全部拆成独立 Skill。只有满足以下条件才拆：

- 输入变量不同。
- 输出结构不同。
- 质量门槛不同。
- 用户心智不同。
- 可在流程中独立选择或替换。

否则保留为同一个 Step 的 `variant`。

## 架构流与写作细化

写作流程要拆成两层。

### 1. 架构设定层

负责建立作品 canon，切换成本高。

包含：

- 世界观
- 主角/配角
- 金手指/力量体系
- 大纲
- 细纲
- 章纲
- 平台和题材承诺

规则：

- 默认使用同一个 Skill Series Flow 保持连贯。
- 允许在步骤边界切换，不允许在同一步中途混用。
- 切换后必须跑一致性检查。
- 输出一旦写入项目设定，就进入 canon，需要版本记录。

### 2. 写作细化层

负责把已定 canon 写成章节，切换成本低。

包含：

- 正文风格
- 对话节拍
- 动作链
- 章首章末钩子
- 去 AI 味
- 拆书获得的风格/节奏/冲突卡

规则：

- 可以按章节、场景、审稿问题叠加。
- 可以试驾对比后切换。
- 不能覆盖 canon，只能改变表达、节奏和兑现方式。

## 拆书卡片到底拆什么

拆书不是把别人的世界观和剧情搬进来，而是拆“可迁移能力”。

### 可以拆出的卡

| 卡片 | 作用 | 可叠加位置 |
| --- | --- | --- |
| 文风卡 | 句式、语气、叙述密度、对白比例 | 正文/精修 |
| 节奏卡 | 章内推进、信息释放、短段落、爆点间隔 | 章纲/正文 |
| 钩子卡 | 章首、章末、付费点、悬念类型 | 章纲/审稿 |
| 角色动力卡 | 主角欲望、对手压力、关系拉扯 | 角色/章纲/正文 |
| 爽点循环卡 | 铺垫-释放-反应-承接 | 大纲/章纲 |
| 世界规则模式卡 | 抽象规则、限制、代价、资源结构 | 世界观/大纲 |
| 平台适配卡 | 番茄完读、知乎反转、老福特关系兑现 | 平台诊断 |
| 反模式卡 | 哪些写法会崩、哪些套路会污染 | 审稿 |

### 不应拆出的内容

- 原作角色名、地名、组织、能力名。
- 具体情节事实。
- 名场面、金句、专属关系。
- 强私有化提示词中的联系方式、自保护协议和个人约束。

### 叠加顺序

正文生成时建议按优先级叠加：

1. 用户当前明确要求。
2. 项目 canon：世界观、角色、时间线、设定。
3. 平台维度：番茄/起点/晋江/知乎等。
4. 题材包：玄幻、言情、克苏鲁等。
5. 当前 Skill Series Flow 的步骤规则。
6. 拆书卡片：只作为表达和结构增强。
7. 通用去 AI 味和审稿规则。

冲突时，canon 高于风格卡，用户意图高于平台商业建议。

## 工作流是否必须一站式到底

不必须。建议采用 **主流程 + 可替换节点 + 可叠加卡片**。

### 三种使用模式

| 模式 | 适合用户 | 产品行为 |
| --- | --- | --- |
| 一站式流程 | 新手、付费高级流程、想省心的用户 | 从脑洞到精修默认一路走完 |
| 节点替换 | 有经验作者、明确知道某一步不满意 | 在世界观/角色/大纲/章纲等边界切换 |
| 写作叠加 | 正文不够像、节奏不够爽、AI 味重 | 保持架构不动，叠加拆书卡/文风卡/平台卡 |

### 什么时候允许切换

- **开书前**：可自由切换流程、平台、题材。
- **世界观生成后**：可切换大纲工具，但需读取既有世界观。
- **大纲生成后**：可切换细纲/章纲工具，但不得改核心承诺。
- **章纲生成后**：可切换正文风格和拆书卡。
- **正文生成后**：可切换审稿和精修工具。

### 什么时候不建议切换

- 一个步骤执行到一半。
- 已写入 canon 的世界观/角色被另一个流程重新定义。
- 平台商业规则与用户明确风格冲突。
- 同时叠加多个强风格正文卡，导致口味互相抵消。

### 用户为什么会切换

- 当前输出不符合目标平台。
- 架构强但文风不满意。
- 文风好但剧情点不够。
- 长篇流程适合大纲，但正文想换成更口语或更克制。
- 审稿发现某类问题，需要临时挂载专项卡。
- 免费流程体验后，想升级为更完整的付费流程。

## 脑洞、灵感、取名的位置

脑洞、灵感、取名不应作为重型流程入口。它们更适合内置到 Agent 对话里：

- 用户开书时自然触发。
- Agent 发现缺书名/简介/核心卖点时推荐。
- 输出可以写入项目资产，但默认不长期挂载。
- 高级版本可以进入付费流程包，但基础版应免费。

因此：

- 小说命名 = Agent 内置工具 + 可保存结果。
- 灵感脑洞 = 开书对话能力 + 可转方向卡。
- 五个脑洞类提示词 = 输出多候选，不拆成五张 Skill。

## 发布平台、长短篇、审稿、题材的定位

这些不是孤立功能，而是流程强化维度。

| 维度 | 本质 | 作用位置 |
| --- | --- | --- |
| 平台 | 竞争环境和读者预期 | 开书、章纲、审稿、精修 |
| 长短篇 | 篇幅结构和兑现节奏 | 开书、大纲、章节循环 |
| 审稿 | 质量门禁和重写决策 | 写完后、发布前 |
| 题材 | 世界规则和读者承诺 | 世界观、角色、大纲、正文 |
| 文风 | 表达口味 | 正文、续写、精修 |

平台和题材可以共同作用，例如：

- 番茄 + 玄幻长篇：快节奏、爽点密度、章末钩子、升级体系。
- 晋江 + 古言：关系推进、人物动机、文案承诺。
- 知乎 + 短篇：强导语、反转、付费前信息压缩。
- 老福特 + 同人：CP 关系兑现、圈层语境、角色一致性。

## 盈利与包装判断

不按单条 prompt 售卖，按“降低创作失败率的流程能力”售卖。

### 免费层

- 内置基础 Agent。
- 基础脑洞、取名、简介。
- 广场免费 Skill。
- 基础题材 profile。
- 基础审稿和去 AI 味扫描。
- 平台基础建议。

目标：让用户完成从灵感到第一章的闭环。

### 付费层

- 作者 Skill Series Flow：如小飞鸡长篇流。
- 高级平台包：番茄长篇完读诊断、知乎短篇付费点诊断。
- 长篇稳定性：十章循环、剧情点预算、章节 commit。
- 高级拆书：前十章拆解、对标书抽象转化、拆书卡生成。
- 高级主编 Agent：blocking 问题、局部手术、发布前诊断。
- 私有资产导入与个人流程编排。

目标：卖稳定结果、连续流程、平台适配和省时间，而不是神秘提示词。

## 定制提示词是否优先

产品判断：在同一维度、同一任务、同一题材下，定制提示词通常比广场提示词更完整、更细、更有流程约束。原因是定制提示词往往服务明确用户、明确题材、明确输出场景，包含更多变量、分支、质量门槛和禁止事项。

用户已确认购买授权后，优先级不再受 `has_access=false` 阻断，但必须受白标清洗和质量复评约束。

### 替代规则

| 情况 | 主版本 | 处理 |
| --- | --- | --- |
| 定制质量高于广场，且已完成白标清洗 | 定制 | 作为 direct-use-test 或付费流程节点 |
| 定制质量高但未清洗 | 广场/内置暂顶 | 定制进入 sanitize-productize，清洗后再替代 |
| 广场质量高且稳定 | 广场 | 可作为免费 Skill 或流程入口 |
| 定制强私有化、平台/题材过窄 | 不替代 | 只做题材结构参考 |
| 定制和广场各有优势 | 主版本 + 辅助卡 | 定制做主流程，广场做免费入口或补充卡 |

### 同类资产选择顺序

1. 白标状态：已清洗、可运行时使用的资产优先；未清洗原文不能进入用户可见产品。
2. 质量：变量清晰、输出稳定、步骤完整、质量门槛明确者优先。
3. 适配：与目标平台、题材、篇幅、用户阶段更贴近者优先。
4. 连贯：同一作者流程内节点优先，避免中途换工具导致语义漂移。
5. 可解释：能解释为什么推荐、为什么替换、风险是什么。

### 小飞鸡示例

小飞鸡长篇的可用定制节点质量明显高于多数广场同类节点：

- `private-178` 长篇细纲比通用章节大纲更适合十章循环。
- `private-157` 角色卡比普通角色生成更适合长篇主角/配角分层。
- `private-177` 世界观比广场世界观工具更完整。
- `private-193` 去 AI 味比普通润色更像质量门禁。

因此在“小飞鸡长篇流”内，优先使用这些可用定制节点；广场节点负责免费入口、补充能力或试驾。

### 付费触发时机

- 用户已完成免费开书，但前十章不稳。
- 用户明确选择商业平台。
- 用户反复使用某个免费流程节点。
- 用户需要长篇连续生产。
- 用户导入私有提示词或参考书，想形成个人流程。

## 决策原则

- 作者流程优先保持连贯，但不强制用户一路到底。
- 架构层切换要谨慎，写作层叠加要灵活。
- 拆书卡只迁移能力，不迁移内容。
- 平台是诊断和推荐维度，不是全局写法。
- 免费让用户完成闭环，付费卖稳定流程和高级诊断。

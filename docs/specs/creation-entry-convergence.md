# 规格：创作入口定位收敛（「首页」×「AI 协作」）

Labels: ready-for-agent
Status: 待确认（test seams 需实现者复核）
Source: 会话 JTBD 冲突分析（2026-09）

## Problem Statement

一个想开新书"user"面对两个都能"从灵感到开书"的入口：首页的灵感输入框（快速立项向导），和「AI 协作」入口在无书状态下展开的方案卡孵化流程。两者命名不做区分、互不导流、数据不互通——用户不知道该从哪里输入灵感，从一条路径进来的种子到另一条路径要重新输入。同时侧边栏「开始创作」实际是一个控制台页面而非动作，命名与用户心智错位。

## Solution

不合并两套开书流程，而是**把冲突消解为分工**：

- 首页 = 创作控制台，占"快速开书"任务（灵感输入 → 立项候选 → 方向确认 → 开书）。
- AI 协作 = 协作层：书内是写作副驾（现状不变），无书态明确为"灵感孵化"（方案卡可混卡、换一批、逐步设定）。
- 两条路径之间建立**带种子的互链**：首页输入的灵感可一键进入孵化；孵化中的方案可一键回到快速开书。
- 命名理顺：侧边栏「开始创作」改为「首页」，把"开始创作"这个动词留给真正的动作；无书态抽屉显式标识"灵感孵化"。

## User Stories

1. 作为新用户（书库为空），我想在首页输入一句灵感就得到立项候选并确认开书，这样我不用理解 AI 协作的概念也能开始。
2. 作为新用户，我点侧边栏「AI 协作」时，能看到"这里是灵感孵化、可慢慢细化方案"的明确说明，这样我不会以为点错了地方。
3. 作为有模糊灵感但拿不准方向的用户，我想在首页输入灵感后一键"让 AI 多出几个方案"，这样同一个种子不用重新输入就能进入方案卡孵化。
4. 作为正在孵化方案的用户，我想一键把当前种子带回首页的快速开书向导，这样我不想要多方案时不会被流程困住。
5. 作为孵化中的用户，我选中一张方案卡后，想继续按设定任务逐步细化并开始创作，这样孵化成果不丢失（现状行为保持）。
6. 作为老用户，我想在首页"继续当前作品"直接回到最近的书，这样回书路径不受本次改动影响。
7. 作为书内写作的用户，我点「AI 协作」得到正文候选、分镜、设定、碎片等章节协作，这样书内协作体验完全不变。
8. 作为使用快捷键的用户，我把「AI 协作」定义为唤起助手而非切换视图，这个语义保持不变。
9. 作为扫侧边栏找功能的用户，我看到「首页」「我的书库」「创作工作台」「AI 协作」，能准确猜到每一项的含义，"开始创作"不再是一个页面名。
10. 作为从首页快速开书流程走到"创作方向确认"的用户，我在这一步能看到"想要更多方案？去灵感孵化"的引导，这样我在决策点而不只是入口处被导流。
11. 作为从孵化流程回来的用户，我点"直接快速开书"时，首页输入框已被填入孵化中的种子，我不需要复制粘贴。
12. 作为开发者，两套开书数据模型（立项候选结果 / 孵化草稿）在本次改动中保持原样，这样回归风险可控。

## Implementation Decisions

- **定位重述（核心决策）**：「灵感→开书」这个任务是两个重量级版本并存——快速档（同步立项推荐向导）与孵化档（异步 LLM 方案卡）。本次**只做入口分工与导流，不合并实现**。合并后端留待入口分工上线、有使用数据后再评估。
- **命名**：侧边栏主项「开始创作」改label为「首页」；视图 id、路由、快捷键映射全部不变。「AI 协作」label 不变（书内语义准确）。无书态抽屉 onboarding 模式头部增加模式标识「灵感孵化」与一句定位说明。
- **互链（新增的两个动作，全部复用现有通道）**：
  - 首页灵感输入区新增「让 AI 多出几个方案」动作：以当前输入为 `ideaSeed` 调用现有的孵化草稿创建流程并打开抽屉孵化模式（该流程本就接受外部种子，无需新接口）。
  - 抽屉孵化模式新增「直接快速开书」动作：以当前种子（输入框内容或选中方案卡的钩子）回首页并填入快速向导的灵感输入框。
- **导流点位**：除入口外，在首页"创作方向确认"弹窗内追加一条到孵化模式的文字引导（决策点导流）。
- **默认主路径**：书库为空时首页引导文案维持"输入灵感生成立项候选"为主 CTA；孵化模式不做首屏抢占，仅在被点开时说明自身定位。
- **不改动**：视图 id 与快捷键、两套数据模型、书内助手全部行为、拆书工厂/资料续写入口。

## Testing Decisions

- 只测外部行为（渲染出的文案、点击后的导航/开抽屉回调及携带的种子），不测组件内部 state。
- Seam 一（最高、最便宜）：侧边栏导航项为纯函数导出，直接断言「首页」label 与项序——一个新断言即可，防命名回退。
- Seam 二（行为主 seam）：复用现有 AppShell 级组件测试模式（仓库已有多个 app-shell 行为测试先例），覆盖三条互链/导流路径（首页→孵化带种子、孵化→首页带种子、确认弹窗引导可见）。
- 回归：现有助手会话与冷启动引导测试必须保持绿；本次为纯前端改动，按测试地图跑前端定向测试即可，不涉及后端。

## Out of Scope

- 两套开书后端（同步立项推荐 vs 异步方案卡生成）的合并或统一数据模型。
- 拆书工厂、资料续写、书库等其他入口的定位梳理。
- 行为埋点与 A/B（建议后续单独做：先量化两条路径的完成率，再决定是否值得合并后端）。
- 移动端/窄屏下的布局适配细节。

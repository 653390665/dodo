# InkFlow 新手起步与故事方案卡设计

## 1. 目标

本设计面向 `AI 协同新手`，产品方向为 `最好写`。

核心目标不是继续堆功能，而是把 InkFlow 现有的灵感功能、设定记忆、创作舞台、Skill 系统串成一条清晰的新手主路径，让用户在几乎不理解内部机制的前提下，也能顺利从一个碎片化念头走到可持续创作状态。

主路径定义为：

`灵感对话 -> 3 张故事方案卡 -> 选中方案 -> 新手引导型设定记忆页 -> 进入创作舞台`

## 2. 为什么这样做

当前 InkFlow 已经具备较强的能力层：

- 灵感助手：可对话、可提取设定、可保存到作品
- 设定记忆：已有 `globalOutline`、`worldRules`、人物/地点/道具/势力/时间线等实体系统
- 创作舞台：已有大纲、规划、质量、Trace、Bible、Skills、Ideas、Foreshadowing、Pacing 等侧栏
- Skill 系统：已有版本化、装配、适配得分、反馈记录

问题不在于能力不足，而在于新手无法自然地走完这些能力之间的路径。

因此第一阶段不是新增一个孤立功能，而是重组入口和承接关系，让用户先被接住，再被引导进入现有系统。

## 3. 方案选择

### 3.1 被采纳方案

采用 `2 + 3` 的渐进组合：

- 第一阶段：把 `灵感 -> 故事方案卡` 做成默认新作品入口
- 第二阶段：将选中的方案卡无缝承接到现有设定记忆页与创作舞台

### 3.2 未采纳方案

- 纯灵感页增强：上线快，但仍像旁路工具
- 创作舞台内直接起步：入口与写作环境不断裂，但对新手第一眼信息密度过高
- 全聊天驱动：自然，但设定容易埋在对话里，后续管理困难
- 全表单驱动：结构清晰，但容易变成问卷体验

## 4. 新手主流程

### 4.1 灵感入口

用户点击 `新作品` 后，不直接创建空白作品，而是先进入灵感对话入口。

灵感入口目标：

- 接住用户碎片化创意
- 通过 2-4 轮轻量对话补全想法
- 避免长问卷和高学习成本

输出结果不是大段文本，而是首批 `3 张故事方案卡`。

### 4.2 故事方案卡

首批默认展示 `3 张`，并支持 `继续刷一批`。

用户可执行的动作：

- 选中一张
- 混搭两张
- 继续刷一批
- 返回补充灵感

`继续刷一批` 不覆盖上一批，避免用户刷新后丢失喜欢的方案。

### 4.3 方案确认后落点

用户选中方案后，不直接进入创作舞台，而是先进入 `设定记忆页`。

原因：

- 先立住设定骨架，减少后续偏离主线
- 对新手来说，先确认方向比立即生成正文更稳

## 5. 故事方案卡结构

每张卡至少包含以下字段：

- `hook`
  - 一句话卖点
- `protagonist`
  - 主角设定摘要
- `coreConflict`
  - 核心冲突
- `tone`
  - 故事气质 / 文风方向
- `whyItWorks`
  - 为什么值得写
- `starterSeeds`
  - `worldSeed`
  - `relationshipSeed`
  - `chapterOneSeed`
- `riskNote`
  - 最容易写崩的点
- `mixTags`
  - 用于混搭两张卡时提取可拼接要素

卡面默认只展示高信号信息，不展示大段正文，避免方案卡退化成难读的 AI 长文。

## 6. 方案卡落库映射

选中方案卡后，不保留为悬空提案，而是立刻映射到现有作品模型：

- `hook + whyItWorks` -> `Novel.summary`
- `coreConflict + chapterOneSeed + 主线方向` -> `Novel.globalOutline`
- `worldSeed + tone 中涉及的规则约束` -> `Novel.worldRules`

如果方案卡中已有较明确主角信息，可同步创建一个初始 `Character` 草稿：

- `name`
- `summary`
- `traits`

第一阶段不建议自动创建过多实体，避免把设定记忆页一开始就写脏。

## 7. 设定记忆页的新手承接

### 7.1 承接方式

采用 `新手引导型`，不是直接把用户扔进完整后台。

页面结构：

1. 顶部进度条
2. 左侧关键设定任务卡
3. 右侧常驻设定助手面板
4. 底部放行区

### 7.2 关键设定任务卡

默认展示 4-6 张最关键的卡：

- 主角是谁
- 核心冲突是什么
- 世界规则 / 故事背景
- 关键关系
- 第一章起点
- 风格与读感

每张卡包含：

- 状态：`未开始 / AI 已起草 / 已确认 / 仍待完善`
- 简短摘要
- 快捷动作：
  - `AI 起草`
  - `换一种写法`
  - `继续聊这项`
  - `我自己改`

### 7.3 右侧常驻设定助手

交互选择为 `两者结合`：

- 每张卡上有快捷 AI 动作
- 右侧有统一助手面板承接深入对话

用户点选哪张卡，右侧助手就自动带上该设定项上下文继续协作。

这样既保证低门槛入口，又保留深度干预能力。

### 7.4 放行条件

采用折中放行策略：

- 至少完成 `2-3` 项核心设定后，允许进入创作舞台

这样能避免新手过早开写导致主线漂移，同时不至于把门槛抬得过高。

## 8. 方案卡到设定任务卡的映射

方案卡选中后，系统自动生成首批引导任务：

- `主角卡` <- `protagonist`
- `核心冲突卡` <- `coreConflict`
- `世界规则卡` <- `worldSeed`
- `关键关系卡` <- `relationshipSeed`
- `第一章起点卡` <- `chapterOneSeed`
- `风格与读感卡` <- `tone`

这些卡的默认状态以 `AI 已起草` 为主，而不是空白，降低新手阻力。

## 9. 与现有系统的复用关系

本方案优先复用现有系统，而不是新造平行层。

### 9.1 复用设定记忆

直接复用：

- `Novel.summary`
- `Novel.globalOutline`
- `Novel.worldRules`
- `WorldBibleView` 的实体管理能力

新手引导层只是一层 onboarding shell，底层仍写入现有数据结构。

### 9.2 复用创作舞台

不新建第二套写作工作台。

完成最低设定要求后，直接进入现有 `EditorView`。

### 9.3 复用灵感助手

现有灵感助手不废弃，而是从“聊天工具”升级为“新作品主入口的第一步”。

## 10. 与 Skill / 拆书系统的联动

### 10.1 第一阶段联动目标

用户选完故事方案卡后，系统自动推荐 `3 张` 最适合的 Skill。

### 10.2 为什么需要联动

如果不联动，会出现三套语言体系：

- 故事方案卡：方向型信息
- 设定记忆：实体型信息
- Skill / 拆书：写作能力型信息

第一阶段目标不是统一三者底层结构，而是先让它们能互相理解。

### 10.3 联动方式

采用 `轻度联动`：

- 故事方案卡和设定页共享一套轻量故事维度标签
- Skill 仓库继续使用现有 `primaryDimension / dimensionTags / compositionProfile`
- 两者通过映射关系联动，而不是强行共用同一张数据表

建议的故事维度标签：

- `tone`
- `conflictType`
- `worldWeight`
- `characterWeight`
- `pacingPreference`

映射到 Skill 维度：

- `tone` -> `style`
- `characterWeight` -> `character`
- `worldWeight` -> `world` / `power`
- `conflictType` -> `plot`
- `pacingPreference` -> `pacing`

### 10.4 推荐策略

第一阶段采用 `纯规则推荐`：

- 根据故事方案卡维度标签
- 匹配现有 Skill 的 `primaryDimension / dimensionTags / compositionProfile`
- 输出 3 张推荐 Skill
- 每张卡带一句推荐理由

推荐结果应在设定记忆页顶部展示，并支持一键接受写入现有 `mountedSkillLoadout`。

第一阶段不做：

- 复杂模型语义排序
- 用户可调推荐偏好
- 双向复杂联动

## 11. 第一阶段产品范围

第一阶段只做以下闭环：

1. 新作品入口从空白创建改为灵感起步
2. 灵感对话输出 3 张故事方案卡
3. 方案卡选中后创建作品并落库到现有字段
4. 进入新手引导型设定记忆页
5. 至少完成 2-3 项核心设定后进入创作舞台
6. 自动推荐 3 张最适合的 Skill，并支持一键接受

## 12. 非目标

第一阶段不做以下内容：

- 方案卡完整中台化
- 方案卡、Skill、设定记忆的统一底层 schema
- 复杂 AI 推荐排序
- 自动生成完整正文作为默认第一落点
- 自动创建大量实体设定

## 13. 成功标准

如果第一阶段做对，用户体验上应出现以下变化：

- 新手不再从空白作品开始
- 用户能在低压力下从灵感进入可执行故事方向
- 设定记忆从“后台库”变成“可被引导完成的骨架搭建区”
- 创作舞台接入时，用户已经带着更稳的主线和初始 Skill 进入
- InkFlow 的核心感知从“功能很多”转向“更容易开始写”

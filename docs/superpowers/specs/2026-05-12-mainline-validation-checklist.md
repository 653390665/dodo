# InkFlow 主线路径验证 Checklist

## 1. 目的

这份清单只验证主线路径是否顺手，不验证所有功能是否完整。

主线定义：

`开始创作 -> 进入作品 -> 进入当前章节 -> 写作推进 -> 卡住时唤起灵感助手 -> 结果落地 -> 继续写`

## 2. 自动验证结果

以下检查已由当前会话执行：

- `http://127.0.0.1:3001/` 返回 `200 OK`
- `node --import tsx --test tests/*.test.ts`
  - 73/73 通过
- `npm run lint`
  - 通过
- `npm run build`
  - 通过（如出现 chunk size warning，可记录但不算主线路径失败）

## 3. 手动验证场景

以下场景必须在 UI 中手动走一遍。

---

## 场景 A：新建作品入口是否清楚

入口：

- 侧边栏 `开始创作`

检查项：

- [ ] 首屏文案清楚表达“这是新建作品入口”
- [ ] 输入一个模糊想法后，能生成 3 个故事方向
- [ ] 选择一个方向后，系统确实创建新作品，而不是只停在灵感聊天
- [ ] 创建完成后，能进入作品内工作流，而不是回到泛首页

判定标准：

- 用户无需理解其他页面，也能从 0 到 1 建出作品

失败信号：

- 用户会犹豫“该去开始创作还是灵感助手”
- 选故事方向后，不知道作品是否已经真正建立

---

## 场景 B：进入工作台后是否知道先做什么

入口：

- 从书库进入已有作品
- 或从新建作品完成后进入

检查项：

- [ ] 用户能一眼知道当前正在处理哪一章
- [ ] `写作优先 / 设定优先` 的区别能被直观理解
- [ ] 工作台不会让用户先去管理工具，而是自然回到“继续写”

判定标准：

- 当前章节是主视觉中心
- 下一步动作清楚可见

失败信号：

- 用户进入工作台后先看见的是工具，不是章节
- 用户不确定该先写正文、补分镜，还是点 AI

---

## 场景 C：卡住时是否会自然使用灵感助手

入口：

- 在当前章节里写一段正文，或选中一小段文本
- 点击 `带上下文打开灵感助手`

检查项：

- [ ] 助手页面明确展示当前作品/章节/目标
- [ ] 用户能理解这是“围绕当前章节”工作，而不是脱离项目聊天
- [ ] 助手回复的候选类型标签（正文候选/分镜候选/设定候选/碎片候选）能被理解
- [ ] 主动作按钮看起来确实是最优落点

判定标准：

- 用户打开助手后不会觉得自己离开了当前写作任务

失败信号：

- 助手上下文信息太弱，用户感觉像在重新开一个聊天
- 回复下动作过多，虽然分类了但还是不知道该点哪个

---

## 场景 D：助手结果是否能低摩擦落地

入口：

- 在灵感助手里拿到一条回复

检查项：

- [ ] 当有选区时，`替换当前选区` 的意图是明确的
- [ ] `插入正文末尾` 是否符合正文候选的直觉
- [ ] `追加到场景分镜` 是否符合分镜候选的直觉
- [ ] `提取到当前作品设定` 是否符合设定候选的直觉
- [ ] `保存为灵感碎片` 是否符合碎片候选的直觉

判定标准：

- 用户看到主动作后，基本不需要再读完整排按钮

失败信号：

- 用户先看按钮，再反推这条建议是什么
- 用户重复点错动作

---

## 场景 E：落地完成后是否能继续写

入口：

- 完成一次助手结果落地

检查项：

- [ ] 落地后，用户能自然回到当前章节
- [ ] 正文替换/追加后，用户不需要重新找当前位置
- [ ] 分镜追加后，用户知道下一步是继续扩写还是继续求助
- [ ] 设定和碎片落地不会打断主写作节奏

判定标准：

- 每次辅助完成后，用户能无缝回到“继续写”

失败信号：

- 每次落地后都像完成一个后台操作，而不是推进写作

## 4. 记录模板

每走完一个场景，按以下格式记录：

```md
### 场景 X
- 是否通过：
- 卡点：
- 用户是否犹豫：
- 最不顺手的一步：
- 是否需要改代码：
```

## 5. 通过标准

如果以下 4 条同时成立，可认为主线已初步成立：

- 用户知道从哪里开坑
- 用户知道当前章节是主场
- 用户卡住时会自然叫出助手
- 用户能把助手结果落地后继续写

只要有一条不成立，就优先修主线，不继续扩功能。

## 6. 推荐执行顺序

如果现在只做一轮最小验证，按下面顺序走：

### 第一步：新建路径

1. 打开 `开始创作`
2. 输入一句模糊想法
3. 选择一个故事方向
4. 确认是否真正创建作品并进入项目内

目标：

- 验证“从 0 到 1 开坑”是否清楚

### 第二步：主写作路径

1. 进入 `创作工作台`
2. 找到当前章节
3. 直接写几句正文
4. 看是否自然知道下一步动作

目标：

- 验证工作台是否像主稿桌，而不是工具页

### 第三步：卡顿求助路径

1. 在当前章节里选中一段文字
2. 点击 `带上下文打开灵感助手`
3. 等一条回复
4. 观察它的候选类型和主动作

目标：

- 验证助手是否像“当前章节的顾问”

### 第四步：落地路径

1. 对同一条建议尝试一个落地动作
2. 观察是否能回正文或分镜继续写

优先验证顺序：

- `替换当前选区`
- `插入正文末尾`
- `追加到场景分镜`

目标：

- 验证辅助是否服务“继续写”

## 7. 本轮建议只记录 3 类问题

为了避免验证时重新陷入细节优化，这一轮只记录以下问题：

1. **不知道去哪**
   - 用户不确定应该点哪个页面

2. **不知道下一步**
   - 用户进入页面后，不知道先做什么

3. **知道功能，但用起来断**
   - 用户理解功能，但它打断了写作节奏

不记录以下内容，除非它直接阻断主线：

- 视觉细节不够精致
- 按钮文案还可以更顺
- 可再加一个快捷动作

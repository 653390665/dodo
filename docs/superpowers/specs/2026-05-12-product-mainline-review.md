# InkFlow 产品主线评审与冻结清单

## 1. 当前判断

InkFlow 现在已经不是“功能零散的 AI 写作器”，而是初步成形的小说创作工作流系统。

当前最重要的变化不是又多了什么功能，而是已经存在一条真实主线：

`开始创作 -> 进入作品 -> 进入当前章节 -> 写作推进 -> 卡住时唤起灵感助手 -> 结果落回正文/分镜/设定/碎片 -> 继续写`

这条主线一旦成立，后续开发的优先级就不该再按“还能补什么功能”排序，而应该按“是否强化主线”排序。

## 2. 一级路径

### 2.1 新建路径

入口：

- `开始创作`

目标：

- 从一个模糊想法快速变成一个可进入写作的项目

当前已具备：

- 想法输入
- 故事方案卡生成
- 选卡后自动建作品
- 自动创建首章与初始主角草案

结论：

- 这条路径已经够用，不应继续在这里叠加创作中工具。

### 2.2 主写作路径

入口：

- `创作工作台`

目标：

- 让作者始终围绕“当前章节”推进

当前已具备：

- 双栏工作台
- 写作优先 / 设定优先
- 章节编辑
- 分镜编辑
- 世界观上下文
- AI 协作入口

结论：

- 这是绝对主场，后续设计必须优先保护它的连续写作节奏。

### 2.3 卡顿求助路径

入口：

- 从工作台带上下文打开 `灵感助手`

目标：

- 当用户卡住时，快速获得可落地候选内容

当前已具备：

- 带作品/章节/选区上下文打开
- 助手候选类型判断
- 主动作推荐
- 正文/分镜/设定/碎片落地

结论：

- 这条路径已经从“可用”进入“可评估”阶段。
- 现在应验证用户是否顺手，不应继续无上限细抠动作按钮。

## 3. 二级路径

### 3.1 设定记忆

定位：

- 结构化沉淀层

职责：

- 存放被确认的人物、地点、物品、规则、时间线等

要求：

- 只承载“已确认信息”
- 不抢写作主线

### 3.2 灵感碎片

定位：

- 非正式素材池

职责：

- 存放未正式进入正文或设定的创作材料

要求：

- 足够轻
- 不要求高结构
- 主要服务于“稍后再用”

### 3.3 我的书库

定位：

- 项目切换层

职责：

- 找作品、进作品、回作品

要求：

- 保持轻量
- 不演变成运营首页或第二仪表盘

## 4. 当前最大的风险

### 4.1 灵感助手过重

当前风险不是功能不足，而是：

- 助手正在接越来越多动作
- 一条回复下可以落到多个目标
- 如果继续扩张，它会逐渐像第二个工作台

必须守住的边界：

- 助手只负责候选生成与触发落地
- 不负责长期浏览项目状态
- 不负责承载正式写作主状态

### 4.2 工作台被工具化打断

如果后续每次都把作者从当前章节拉去管理候选、碎片、设定、建议类型，那么系统会越来越聪明，写作会越来越断。

必须守住的原则：

- 所有辅助都要回到“继续写这一章”
- 工作台是主稿桌，不是控制台

### 4.3 页面名义清楚但体验主次仍可能模糊

虽然现在 `开始创作 / 创作工作台 / 灵感助手` 的职责已经比之前清楚，但还没经过足够的真实路径验证。

当前真正待验证的不是“功能是否完整”，而是：

- 用户会不会自然走主线
- 用户是否理解不同页面的分工
- 用户是否能在 1-2 次尝试内学会助手怎么帮助自己

## 5. 应冻结的区域

以下区域建议暂时冻结，不再继续扩张：

### 5.1 灵感助手动作面板

冻结原则：

- 不再继续增加新的落地按钮
- 不再增加更多局部动作变体

例外：

- 只有当验证明确显示用户缺一个关键动作时才补

### 5.2 欢迎入口页

冻结原则：

- 不再往 `开始创作` 塞创作中工具
- 不再让它承担项目内编辑行为

### 5.3 工作台内的次级工具入口数量

冻结原则：

- 不继续扩 `agentTab` 类的工具面数量
- 优先看现有工具是否真的服务主写作路径

## 6. 现在值得继续做的，不是更多功能，而是 3 类工作

### 6.1 主线路径验证

要回答的问题：

1. 用户是否知道先去哪
2. 用户卡住时是否会自然打开助手
3. 助手主动作是否符合直觉
4. 用户能否在不理解全部功能的前提下继续推进当前章节

### 6.2 结果结构化，而不是按钮扩张

可以继续做的方向：

- 让助手返回结构化结果
- 每条结果自带类型、推荐落点、风险提示
- Prompt 能力按内部阶段分层组织，不直接暴露为用户主导航。

不该继续做的方向：

- 再堆更多按钮
- 再堆更多落地分支

### 6.3 主场视觉秩序收口

后续若改 UI，优先级应是：

- 强化当前章节
- 强化当前目标
- 强化下一步动作

而不是：

- 强化工具存在感
- 强化 AI 存在感
- 强化“系统很强大”的展示感

## 7. 建议的下一阶段工作顺序

### 第一阶段：停止扩张，做验证

- 手动走主线
- 记录卡点
- 看哪些动作是多余的

### 第二阶段：收口结构化结果

- 让灵感助手返回更明确的候选结构
- 用结构减少按钮理解成本

### 第三阶段：回头清理二级路径

- 检查设定记忆是否过重
- 检查灵感碎片是否过重
- 检查书库是否承担了不该承担的职责

## 8. 产品决策准则

后续每个功能或改动，都先过以下 4 个问题：

1. 它是否强化“继续写这一章”？
2. 它是否让工作台更像主稿桌，而不是控制台？
3. 它是否让助手更像顾问，而不是第二张主稿桌？
4. 它是否减少理解成本，而不是增加动作选择？

只要有 2 个问题答不上来，这个改动就不该优先做。

## 9. 一句话结论

InkFlow 现在缺的不是更多功能，而是对主线的克制。

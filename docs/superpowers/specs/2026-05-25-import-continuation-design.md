# 导入资料续写 Design

## 背景

InkFlow 已经具备“上传资料 -> 解析为 continuation pack -> 批准 -> 在自动生产里接入资料包”的能力，但当前入口挂在“世界设定集 -> 资料续写”下，用户心智更接近“资料管理”而不是“开始一条资料驱动的续写任务”。

这导致三个问题：

1. 用户目标与入口语义错位。用户要做的是“带资料接着写”，不是“维护设定资料”。
2. 关键状态过于隐式。虽然编辑器会默认选中最新 approved pack，但用户没有明确进入“资料包续写模式”的感知。
3. 路径断裂。上传、确认、回到编辑器、打开智能管家、切到自动生产，这条链路在功能上可用，但不符合主线创作流。

## 目标

在不大改现有底层解析与生产链路的前提下，为“带世界观/大纲/任务/已有正文来继续写”的场景建立一个首页一级入口，把它产品化为一条独立任务主线。

本阶段采用：

- 实现范围：方案 A（最小改法）
- 命名与心智：方案 B（主线语义）

## 非目标

本阶段不做以下事情：

- 不重写 continuation pack 的数据结构
- 不重做资料解析逻辑或 prompt
- 不删除现有“世界设定集 -> 资料续写”页面
- 不引入新的复杂状态机或跨项目协同能力

## 用户故事

### 主故事

作为一个带着外部资料来接盘/续写小说的用户，我希望从首页直接进入“导入资料续写”，先看到这条流程会怎样工作，再上传资料并确认系统理解结果，最后直接进入续写，而不是自己再去找编辑器和自动生产入口。

### 次故事

作为一个已经导入过资料包的用户，我希望旧入口继续存在，用于查看、管理、补充、删除资料包，而不是承担第一次进入这条创作主线的责任。

## 设计原则

1. **任务优先，不是资料优先**
   用户进入的是“续写任务”，不是“资料管理台”。

2. **关键状态显式化**
   用户要清楚自己当前是否处在“资料包续写模式”，当前接入的是哪份资料包。

3. **确认后直接写**
   审核资料包后的下一步必须是“进入续写”，不是“回去再找功能”。

4. **实现先小步，语义先做对**
   本阶段复用现有能力，但界面命名、入口层级、跳转关系按最终主线设计。

## 信息架构调整

### 新增主入口

在首页主创作区域新增一级入口：

- 名称：`导入资料续写`
- 位置：与“开始创作”同区域，作为并列主入口
- 辅助文案：`上传世界观、大纲、任务或已有正文，整理后直接进入续写`

### 现有入口降级

现有“世界设定集 -> 资料续写”保留，但产品语义调整为管理入口，后续推荐改名为：

- `资料包管理`
或
- `续写资料管理`

该入口负责历史查看、重审、删除、补充，而不是承接第一次使用路径。

## 页面流

### Flow

`首页 -> 导入资料续写 -> 资料包确认 -> 进入编辑器自动生产`

### 1. 首页

用户在首页看到两条并列主线：

- 从零开写
- 带资料续写

点击 `导入资料续写` 后进入专属导入页。

### 2. 导入资料续写页

目标：先建立流程预期，再开始上传。

页面结构：

- 标题：`导入资料续写`
- 一句话说明：`把世界观、大纲、任务说明、已有正文交给系统，先整理成资料包，再开始续写。`
- 四步流程说明：
  - `上传资料`
  - `AI解析`
  - `人工确认`
  - `进入续写`
- 上传区：
  - 多文件拖拽/选择
  - 支持 `.txt .md .json .docx`
- 资料类型提示：
  - `世界观`
  - `大纲`
  - `任务`
  - `已有正文`
- 作品归属方式：
  - `续写到现有作品`
  - `导入后新建作品`
- 主按钮：`解析资料包`

交互要求：

- 未选文件时按钮不可点
- 选择“续写到现有作品”时必须先选作品
- 选择“新建作品”时可用资料包标题自动生成默认作品名

### 3. 资料包确认页

目标：让用户确认“系统理解对了”，而不是进入复杂资料管理界面。

页面只展示五块核心信息：

- `续写任务`
- `当前剧情锚点`
- `关键硬设定`
- `人物状态`
- `资料缺口 / 风险`

辅助信息：

- 来源文件数
- 最近更新时间
- 是否存在冲突

主动作：

- 次按钮：`返回调整资料`
- 主按钮：`确认并进入续写`

交互要求：

- 如存在严重冲突，主按钮禁用，或显示风险提示
- 点击确认后，将 pack 置为 `approved`
- 同时将该 pack 作为本次续写流的默认 active pack

### 4. 进入续写

点击 `确认并进入续写` 后，直接跳到目标作品编辑器，并自动完成：

- 打开智能管家
- 切换到 `自动生产`
- 默认选中刚批准的资料包

同时在生产面板顶部增加明确状态表达：

- `当前模式：资料包续写`
- `已接入资料包：<pack title>`
- `续写任务：<task summary>`

现有资料包摘要卡保留，但语义上应服务于“当前任务”而不是“资料详情浏览”。

## 方案 A 的实现范围

本阶段仅做以下最小改动：

1. 首页新增 `导入资料续写` 入口
2. 新建轻量导入页
3. 新建轻量确认页
4. 复用现有 continuation pack 解析与批准逻辑
5. 确认后跳转到现有编辑器，并自动打开自动生产面板
6. 保持原“世界设定集 -> 资料续写”页可用

## 与方案 B 的边界

未来如升级到完整主线方案 B，再继续做：

1. 正式把旧入口改名为 `资料包管理`
2. 将“资料对象管理”和“续写任务启动”彻底拆分
3. 在编辑器中增加更显式的“资料包续写模式”状态条与 CTA
4. 将首页、确认页、编辑器串成独立主线，而不是复用更多旧管理页面结构

## 核心风险

1. **导入页过重**
   如果导入页一次塞太多设置项，会失去首页主入口的轻量优势。

2. **确认页重新演化成管理页**
   如果确认页堆太多结构化信息，用户会重新掉回“资料维护”心智。

3. **进入编辑器后的模式感不足**
   如果跳转后没有明确状态条，用户仍可能怀疑资料包是否已真正接入。

## 验收标准

满足以下条件时，本设计视为达标：

1. 用户能从首页直接进入 `导入资料续写`
2. 用户在上传前能理解完整主流程
3. 用户批准资料包后会直接进入续写，而不是自行寻找下一步
4. 进入编辑器后，自动生产面板默认选中刚批准的资料包
5. 用户在 UI 中能明确感知当前处于“资料包续写”语义下

## 推荐实施顺序

1. 首页新增入口
2. 导入页
3. 确认页
4. 跳转到编辑器自动生产
5. 编辑器顶部状态表达补强

## 一句话收口

本阶段不是在“给资料包能力补一个入口”，而是在用最小改动，把它从一个隐藏能力改造成一条看得见、走得通的续写主线。

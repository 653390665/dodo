## 246: 分镜来源徽标不诚实（双端，S-M）

**根因**：前端徽标读内存 store（刷新后 null）而非 DB `degradation.beatsSource`；后端纯保底 run 落库时根本没写 degradation 字段。

**修法**：
- 后端 `production.ts:819-825 + 525-531`：`fallbackContinuity` 补 `degradation: { beatsSource:'fallback', draftSource:'fallback' }`
- 前端 `ProductionRunReview.tsx:350`：徽标数据源改为 `displayRun?.continuityReport?.degradation?.beatsSource ?? beatsSource`
- 历史存量纯保底 run（degradation undefined）前端兜底：`auditMeta.source==='fallback'` 时也标降级

**Verify**：保底 run 的 UI 徽标显示 ⚠️；模型 run 显示 AI 分镜；历史列表一致。

## 247: 生产期 critic unknown 自动重试（后端，S）

**根因**：`ai-production-pipeline.ts:642` unknown 直接 break 终止循环（不重试 critic 也不回炉 Writer），导致审计状态永远 unknown。

**修法**：unknown 时对 critic 追加一次复核重试（CRITIC_PARSE_RETRIES 从 1 提到 2，或在 unknown 路径加一轮 critic-only 重试）；复核仍 unknown 则维持现状（诚实降级）。

**Verify**：后端定向测试——mock critic 首次返回无证据 JSON → 重试后返回完整证据 → 最终 status=pass；两次均 unknown → 正确降级。
